# Правила проекта

## Общие положения

Этот документ описывает соглашения и правила, принятые в проекте для обеспечения консистентности кода, улучшения читаемости и облегчения сопровождения.

## Взаимодействие человека и нейросети в процессе разработки приложения

1. **Перед каждым действием уточняй у человека, правильно ли ты все понял, чтобы избежать ошибок и сэкономить время и токены**
2. Если что-то не понятно и имеется нехватка информации, ничего не надо выдумывать своё, просто - спроси или уточни всё что вызывает не понимание.
3. Не торопись с суждением, лучше уточняй верны ли твои рассуждения и правильно ли твое понимание поставленной задачи
4. При нехватке информации или непонимании глобального замысла, всегда уточняй у человека перед тем как принимать решения
5. Избегай избыточной работы, учитывая уже существующую функциональность в проекте
6. Постоянно следуй системному файлу rules в Kilo Code и правилам проекта, поминая об их приоритетах
7. Перед выполнением задачи пересмотри файлы rules и PROJECT_RULES.md, чтобы избежать спешки и неточностей
8. Регулярно удостоверяйся, что правильно понимаешь задачу и этап разработки, на котором находится проект

## Работа со стилями

### Порядок свойств в SCSS

- Миксины должны быть расположены после всех остальных CSS свойств в селекторе класса
- Это обеспечивает лучшую читаемость и следование новым правилам в SCSS

### Адаптив
-При адаптиве старайся использовать  связку CSS Grid + Container Queries. Так же не забывай о миксинах.

-Когда имеешь дело с блоком, где имеется мнжество элементов, например как в большом footer - можешь использовать grid-template-areas как основа стилизации

-В проекте преимущественно используются адаптивные единицы измерения. В файле `_functions.scss` имеются следующие функции, которые используются вместо - `px` в стилях:
``` scss
//REM
@function toRem($px) {
	$result: math.div($px, 16) + rem;
	@return $result;
}
//EM
@function toEm($px, $current: 16) {
	$result: math.div($px, $current) + em;
	@return $result;
}
```
-Миксины в SCSS должны размещаться в конце селектора класса, после всех других CSS свойств

### Импорт SCSS миксинов и переменных
1. **Глобальные импорты SCSS**:
   - Все SCSS миксины, функции и переменные импортируются глобально через `nuxt.config.ts`
   - В Vue компонентах не требуется использовать директивы `@use` для импортов
   - Все миксины доступны напрямую в блоках `<style>` компонентов

#### Пример правильного использования
```vue

<style lang="scss" scoped>
.example {
  display: flex;
  flex-direction: column;
  color: var(--text-color);
  // Миксин расположен в конце, после всех CSS свойств
  @include adaptiveValue("font-size", 16, 14);
}
</style>
```
#### adaptiveValue
- Используется для адаптивности с зависимостью от ширины вьюпорта
- Применяется для глобальных стилей (body, h1, h2 и т.д.)
- Синтаксис: `@include adaptiveValue("свойство", начальное_значение, минимальное_значение)`

#### containerParent
- Используется для задания типа контейнера (container-type) или именованного контейнера (container)
- Синтаксис: `@include containerParent(тип_контейнера, имя_контейнера)`
- Параметры:
  - `тип_контейнера` (необязательный): тип контейнера (inline-size по умолчанию)
  - `имя_контейнера` (необязательное): имя для именованного контейнера
- Примеры:
  - `@include containerParent;` - задает container-type: inline-size
  - `@include containerParent(block-size);` - задает container-type: block-size
  - `@include containerParent(inline-size, "my-container");` - задает container: "my-container" / inline-size

#### containerAdaptive
- Используется для автоматической адаптивности с поддержкой Container Queries
- Адаптируется к ширине контейнера, а не вьюпорта
- Имеет fallback к viewport units для старых браузеров
- Синтаксис: `@include containerAdaptive("свойство", минимальное_значение, коэффициент, максимальное_значение)`
- Пример: `@include containerAdaptive("font-size", 14px, 2.5, 18px)`
