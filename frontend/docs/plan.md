## Реализовано 05.09.2026 (ShowHamburger ↔ Hero ↔ ShowShopFilter, часть §1)

Правки в `ShowHamburger.vue`, `HeroSection.vue`, `styles.scss` (не закоммичено):

1. **Диалог каталога больше не наезжает на кнопку (desktop).** Причина: `position-area: bottom span-right` + следующий за ним `inset: auto` — shorthand `inset` сбрасывал инсеты в `auto`, диалог оставался в static-position и верх его был = верх кнопки + `margin-block-start:22` (наложение 41px из 64px кнопки). Заменено на надёжное: `.hamburger { position:relative }`, диалог — `position:absolute; inset:auto; inset-inline:0 auto; top: calc(100% + toRem(22))` (верх = низ обёртки кнопки + 22px; порядок свойств важен: `inset:auto` ДО `top`). Планшетный mobile-инстанс (769–1023, кнопка 150px справа) раскрывается влево (`inset-inline: auto 0`) — не вылезает за правый край.
2. **Hero сдвигается сильнее.** Введён `--catalog-shift: calc(var(--catalog-width) * 1.75)` (`styles.scss`, одна константа для тюнинга). `HeroSection` использует `margin-inline-start: var(--catalog-shift)`. Проверено (1440): сдвиг был 319px → стал 559px; без горизонтального переполнения на 1024–1920.
3. **Desktop-панель каталога открыта по умолчанию только на главной.** Раньше `if (isDesktopInstance) isOpen = true` открывал панель на КАЖДОЙ странице → на `/ru/products` она перекрывала кнопку «Фильтр» (y230..862 поверх кнопки y353) — кнопку нельзя было нажать/закрыть фильтр. Теперь `initialOpen` = desktop && home, а watcher `isHomePage` (путь ≤ 1 сегмента) синхронизирует состояние при SPA-навигации (уход с главной → закрыть, приход → открыть).
4. **SSR/client паритет телепорта (гидратация).** `isMobile` считался от `width=0` → на SSR телепорт в body, на клиенте после замера отключался → Vue гонял dialog (hydration mismatch «expected on client: dialog» + `moveTeleport insertBefore` на /ru/products). Добавлен гейт `viewportReady` (onMounted): и SSR, и первая гидратация рендерят диалог в месте установки; телепорт включается только после монтирования.
5. **Продукты:** desktop-рейл и mobile-механика «шапка сайта уезжает (translateY), страница поднимается на `--header-h`» — без изменений, работают на всех ширинах (рейл + сдвиг карточек, оверлей mobile). Переделка «как ShowHamburger» для фильтра НЕ нужна: у фильтра — сайдбар-семантика (рейл в потоке), а не меню-оверлей; переносить можно только паттерн состояния (компонент самодостаточен, сдвиг делает страница). Проверено: 1440/1600/1920/1024/900/768/390.

**Дополнено (05.09.2026, вторая итерация — главная):**
- **Style guide** (`docs/style/patterns.md` §6): единицы — em (`toEm`) там, где нет container queries; `adaptiveValue` — крайний случай.
- **Сдвиг слайдера** — только у `.hero-slider__slider` (не секции): `margin-inline-start` + `width: calc(100% − var(--catalog-shift))` (USlider даёт `width:100%`, без переопределения был бы переполнение вправо). `--catalog-shift` = `max(0,(100vw−1450)/2) + 15px + --catalog-width + зазор(1.5em)` — «правый край панели + зазор» на любой ширине (старый множитель ×1.75 убран).
- **Анимация сдвига — двухфазный GPU (вариант B):** layout (width/margin/колонки) применяется МГНОВЕННО (`.hero-slider__slider_no-transition`), движение — только `transform: translateX` (класс `_catalog-shifted`, GPU). Layout-класс `_catalog-open` управляется локально (`layoutOpen`), не напрямую от isCatalogOpen.
  - **Открытие:** layout → финал мгновенно → стартовая поза «под панелью» → transform −shift→0 (GPU);
  - **Закрытие:** расширение в полную ширину СРАЗУ (панель ещё открыта, перевёрстка «под ней», один reflow), затем панель закрывается сама (scale). Без «выстрела» в конце — ранее контент дёргался ПОСЛЕ закрытия.
  - Высота диалога (`--catalog-h`) пересчитывается по rAF-цепочке после открытия (Race: HeroSection применяет layout в nextTick, grids едут за высотой секции) + ResizeObserver.
- **Полоса hero-grids** остаётся на всю ширину (привязана к секции, absolute) и не сдвигается; при открытом desktop-каталоге — лёгкий blur(4px) (`is-visible` расширен на `hamburgerCatalogDesktop`). NB: каталог на главной открыт по умолчанию → на desktop полоса блюрится всегда (если нежелательно — скорректировать условие).
- **Слайд при открытом каталоге** (`.hero-slider__slider_catalog-open :deep(.slider__slide)`): `grid-template-columns: minmax(0,1.35fr) minmax(0,1fr)` + `min-width:0` у детей — иначе текст «раздавливался» (48px) из-за несжимаемой колонки `auto` (742px). Закрыто — базовая `auto/1fr` из USlider.
- **Картинка hero** (`UImage &_hero`): `width:100%; max-width: toEm(742); height:auto` — em-кап следует типографике body (на font 16 = 742px). Разница px vs em реальна только когда кап ограничивает (полная ширина, font<16).
- **Высота диалога каталога** — до НИЗА полосы hero-grids: композабл `app/composables/useMeasureToVar.ts` (паттерн `--header-h`) пишет `--catalog-h`; CSS `height: var(--catalog-h, toEm(632))`. Реактивный пересчёт по ResizeObserver `.hero-slider` + триггеру `isOpen`.

## 2. Конвенции адаптива: range-медиазапросы, toEm, containerAdaptive (справка)
### 2.1. Range-медиазапросы (Media Queries Level 4)

Проверка двух границ одной строкой вместо `@media (min-width: A) and (max-width: B)`:

```scss
@media ($mobileSmall <= width <= $tablet) { ... }
// эквивалент «больше-равно» (тоже валидно):
@media ($tablet >= width >= $mobileSmall) { ... }
```

- Значения — переменные из `_settings.scss` (`$mobile`, `$mobileSmall`, `$tablet` — уже в `toEm`).
- Поддержка: Chrome 104+, Firefox 102+, Safari 16.4+.
- Пример в проекте: `@media ($tablet <= width <= toEm(1250))` (FeaturedProductsSection).

### 2.2. «Три кита» адаптива + toEm

Container queries (блок-ширина) + `clamp` (непрерывность) + media queries (вьюпорт). Все значения/брейкпоинты — через `toEm()`/`toRem()` (без «голых» px).

### 2.3. Миксин `containerAdaptive`

```scss
@mixin containerAdaptive(
  $property, $startSize, $minSize,
  $containerFrom, $containerTo,
  $unit: "cqw"
)
```

- Генерирует `clamp(min, calc(yIntercept + slope·cqw), max)` — непрерывная интерполяция по ширине контейнера (в отличие от дискретных `@container`).
- Fallback без CQ — та же кривая по `vw`.
- Использование: высота карточки в `ProductCard.vue` — `containerAdaptive("height", 320, 250, 1000, 360)`; реагирует на ближайший контейнер-предок (`cards` на `ul`), иначе на вьюпорт.
