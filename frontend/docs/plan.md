Правки в `ShowHamburger.vue`, `HeroSection.vue`, `styles.scss` (не закоммичено):

1. **Диалог каталога больше не наезжает на кнопку (desktop).** Причина: `position-area: bottom span-right` + следующий за ним `inset: auto` — shorthand `inset` сбрасывал инсеты в `auto`, диалог оставался в static-position и верх его был = верх кнопки + `margin-block-start:22` (наложение 41px из 64px кнопки). Планшетный mobile-инстанс (769–1023, кнопка 150px справа) раскрывается влево (`inset-inline: auto 0`) — не вылезает за правый край.

**Ключ — как это решено в `ShowHamburger` (образец):**
```vue
<div class="hamburger">            <-- корень: обычный div (в потоке шапки)
  <div class="hamburger-menu">...кнопка...</div>
  <Teleport to="body" :disabled="!isMobile || isDesktopInstance">
    <dialog class="dialog-hamburger">...</dialog>   <-- телепортируется ТОЛЬКО диалог
  </Teleport>
</div>
```
- **Teleport — НЕ корень**, а **ребёнок** внутри обычного `<div>`-корня. Поэтому компонент имеет валидный корень (div), а телепорт (скрывающий диалог) — просто дочерний узел. `:disabled` переключается спокойно (без «фрагмент-корня»).
- **Телепортируется только `<dialog>`** (сам оверлей), а не весь компонент. Корень-`div` остаётся на месте (в шапке/потоке), диалог уходит в `body` и стилизуется как оверлей.
- `:disabled="!isMobile || isDesktopInstance"` — на SSR/desktop **disabled** (диалог в месте установки), на mobile после монтирования — enabled (в `body`). SSR и первая гидратация рисуют ОДИНАКОВО (диалог в месте), затем перенос — без hydration-mismatch.

   - `toolbarGone` — композабл **`useElementGone(target)`** (IntersectionObserver на `container-top`): появится когда блок полностью ушёл за верх (`bottom ≤ 0`), исчезнет при возврате. Наблюдаемый элемент передаётся пропом **`observeTarget`** (или селектор `.products-page__container-top`) — компонент не знает о DOM страницы.
   - Скрытие при `isOpen` (оверлей), `body-lock`/SSR: по умолчанию скрыта (SSR-нейтрально).

4. **п.7 — внутренний close** (если кнопка под оверлеем при fullscreen).
   - На mobile при открытом фильтре кнопка-плавашка скрыта (`isOpen`), а верхняя кнопка (если остаётся под оверлеем) недоступна → добавить **close (X) внутри диалога** (как ShowHamburger). Если верхнюю кнопку оставляем поверх оверлея (z выше) — close не обязателен (решить на шаге 1–2).

5. **Регресс-проверки после переделки** (обязательно прогнать):

## 2. Конвенции адаптива: range-медиазапросы, toEm, containerAdaptive (справка)
### 2.1. Range-медиазапросы (Media Queries Level 4)

Проверка двух границ одной строкой вместо `@media (min-width: A) and (max-width: B)`:

```scss
@media ($mobileSmall <= width <= $tablet) { ... }
// эквивалент «больше-равно» (тоже валидно):
@media ($tablet >= width >= $mobileSmall) { ... }
```

- Значения — переменные из `_settings.scss` (`$mobile`, `$mobileSmall`, `$tablet` — уже в `toEm`).
- Поддержка: Chrome 104+, Firefox 102+, Safari 16.4+.
- Пример в проекте: `@media ($tablet <= width <= toEm(1250))` (FeaturedProductsSection).

### 2.2. «Три кита» адаптива + toEm

Container queries (блок-ширина) + `clamp` (непрерывность) + media queries (вьюпорт). Все значения/брейкпоинты — через `toEm()`/`toRem()` (без «голых» px).

### 2.3. Миксин `containerAdaptive`

```scss
@mixin containerAdaptive(
  $property, $startSize, $minSize,
  $containerFrom, $containerTo,
  $unit: "cqw"
)
```

- Генерирует `clamp(min, calc(yIntercept + slope·cqw), max)` — непрерывная интерполяция по ширине контейнера (в отличие от дискретных `@container`).
- Fallback без CQ — та же кривая по `vw`.
- Использование: высота карточки в `ProductCard.vue` — `containerAdaptive("height", 320, 250, 1000, 360)`; реагирует на ближайший контейнер-предок (`cards` на `ul`), иначе на вьюпорт.
