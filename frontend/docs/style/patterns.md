# Паттерны реализации (style patterns)

Принятые в проекте подходы «задача → реализация» с фокусом на **минимальную нагрузку на CPU**
(анимации на GPU/композиторе, без JS-замеров и циклов).

> Стек: Nuxt 4, Vue 3, SCSS (BEM), Strapi v5.

---

## 1. Класс-биндинги (реактивный класс вместо watch)

**Задача:** менять стиль по состоянию (открыт/закрыт, видимость блока) без лишнего JS.

**Правило:** состояние читаем из глобального `useDialog(id)` (id-only) — тот же ref, что у диалога.
Статичный класс + условные модификаторы — в одном `:class` массиве:

```vue
<!-- любой компонент, которому нужно состояние диалога -->
<script setup>
const { isOpen } = useDialog("shopFilterDialog")
</script>

<template>
  <header :class="['header', { 'header_filter-open': isOpen }]">
</template>
```

- Никаких `watch`/`onMounted` для стилей — реактивность класса это делает сама (минимальный CPU).
- Один источник состояния — `useDialog` хранит `isOpen` в глобальном `Map` по id.

**Альтернатива (когда нужен template-ref):** только если нужен вызов метода дочернего компонента
(например `toggle()` у диалога):

```vue
const shopFilterRef = useTemplateRef<InstanceType<typeof ShowShopFilter>>("shopFilter")
<!-- кнопка: -->
<UButton @click="shopFilterRef?.toggle()" :aria-expanded="shopFilterRef?.isOpen" />
```

Но для **классов** используем `useDialog` (template-ref на SSR = null и не работает вне родителя).

## 2. GPU-анимации (transform/opacity) + CSS-only раскладка

**Задача:** блок плавно исчезает/появляется, соседний контент занимает место — без дёрганья.

**Правило:**
- **transform / opacity** анимируются на GPU/композиторе (`translate`, `translateY`, `opacity`, `visibility`).
- **height/width** — layout (CPU), анимируются аккуратно (или через `interpolate-size`).
- **display** — дискретно: задерживаем `display: none` до конца exit-анимации
  (`transition: display 0s var(--transition-duration) allow-discrete`).

**Пример — шапка исчезает, breadcrumbs + top-bar остаются** (страница товаров, mobile):

```scss
// AppHeader.vue — шапка уезжает вверх (GPU) и освобождает место
.header {
  @media (max-width: $mobile) {
    interpolate-size: allow-keywords;
    transition:
      height var(--transition-duration),
      transform var(--transition-duration);

    &_filter-open {
      height: 0;
      overflow: hidden;
      transform: translateY(-100%);
    }
  }
}
```

```scss
// products/index.vue — страница становится колонкой высотой во вьюпорт:
// breadcrumbs + top-bar в потоке, body (flex:1) заполняет остаток
.products-page {
  // Мобильный flex: зона контента (container-body) заполняет клампнутый вьюпорт
  @media (max-width: $mobile) {
    display: flex;
    flex-direction: column;

    .products-page__header { flex-shrink: 0; }
    // __container-body — flex-ребёнок колонки → авто-маржу [class*="__container"]
    // нейтрализуем (вьюпорт < 1420, центрировать нечего)
    .products-page__container-body {
      flex: 1; min-height: 0;
      margin-inline: 0;
    }
  }
}
```

```scss
// ShowShopFilter.vue — диалог заполняет body, вход снизу вверх (GPU)
.show-shop-filter {
  @media (max-width: $mobile) {
    position: absolute;
    inset: 0;
    z-index: 9999;
  }

  &__dialog {
    translate: 0 100%;               // закрыто — снизу
    opacity: 0;
    transition:
      translate var(--transition-duration),
      opacity var(--transition-duration);

    &[open] { translate: 0; opacity: 1; }
  }
}
```

**Ключевое:** никаких JS-замеров высоты (`getBoundingClientRect`) — раскладка на flex
сама подстраивается под любую высоту breadcrumbs/top-bar. Минимум CPU.

## 3. Container Queries + миксин `containerParent`

**Задача:** компонент адаптируется к ширине своего контейнера, а не вьюпорта.

**Правило:** `@include containerParent(<имя(имена)>, inline-size)`. Имён может быть несколько
через пробел (SCSS-список):

```scss
// ProductCard.vue — карточка = контейнер с двумя именами
.product-card {
  @include containerParent(card productImage, inline-size);
  // card         — свои @container card (max-width: 210px) → front/back
  // productImage — UImage внутри применит свои @container productImage
}
```

```scss
// products/index.vue — контейнер cards на САМОМ списке (ul).
// ul — block-грид: ширина от родителя, поэтому container-type его не схлопывает
// (в отличие от flex-ленты, ширина которой от контента).
.products-page__card-list {
  @include containerParent(cards, inline-size);
}
// Высоту карточки (li) задаёт сам ProductCard.vue через containerAdaptive,
// реагируя на ширину этого контейнера (cqw → ближайший контейнер-предок = ul).
// «2 колонки» на телефонах — медиа-запросом (self-query на ul невозможен):
@media (max-width: $mobileSmall) {
  .products-page__card-list { grid-template-columns: repeat(2, 1fr); }
}
```

Брейкпоинты в `@container` — в пикселях (см. UImage.vue: `@container product (max-width: 256px)`).

## 4. Body-lock при открытом оверлее

**Задача:** при полноэкранном диалоге страница не должна скроллиться.

**Правило:** глобальный `body:has(...)` в `_globals.scss` (только mobile):

```scss
body:has(
  .dialog-hamburger[open]:not(.hidden-tablet .dialog-hamburger),  // скрытый desktop-инстанс исключаем
  .show-shop-filter__dialog[open],
  .chat-assistant__modal[open],
  .cart-dialog[open]
) {
  @media (max-width: c.$mobile) { overflow: hidden; }
}
```

## 5. Синхронный сдвиг контента (анимация ширины)

**Задача:** при сворачивании колонки соседний контент едет **синхронно**, без задержки.

**Правило:** ширина анимируется (`width var(--transition-duration)`), а не «держится и прыгает»
(`width 0s var(...)`); закрытое состояние — явный `width: 0`:

```scss
.show-shop-filter {
  transition:
    display 0s var(--transition-duration) allow-discrete,
    width var(--transition-duration);

  &:has(.show-shop-filter__dialog[open]) { width: var(--filter-width); }

  &:not(:has(.show-shop-filter__dialog[open])) {
    display: none;
    width: 0;   // desktop: плавное схлопывание
  }
}
```

## 6. Единицы измерения: em (toEm) — значение по умолчанию

**Правило:** там, где **нет container queries**, размеры/отступы задаются в **em** через миксин `toEm($px)`.

- `em` резолвится от **computed font-size элемента** (наследуется от `body`, где `adaptiveValue("font-size", 16, 14)`). Это осознанный «резиновый» ритм: вся внутренняя геометрия (в т.ч. капы, `max-width`) масштабируется вместе с типографикой к tablet.
- `px`/`toRem` — только для дизайн-констант, которые **не должны** следовать шрифту (например, ширина ограничивающего контейнера).
- `adaptiveValue` — **крайний случай**, когда `toEm` недостаточно (глобальные размеры по вьюпорту: `h1`, отступы секций).

Пример — кап картинки hero: `max-width: toEm(742)` при font 16 = 742px, на узком desktop (font ~15.25) кап мягко уменьшается до ~707px, синхронно с типографикой. `px` тут дал бы жёсткие 742 и «разошёлся» бы с остальной em-геометрией.

**Важно:** кап/размер в `em` начинает «жить» только когда он реально ограничивает (например, грид уже ужал элемент ниже капа — тогда px и em визуально совпадают). Не путать с «em не работает».

## 7. Маски (`mask` / inverted radius) — стилизация и позиционирование

Практические правила, собранные на реальных ошибках карточки товара.

### Маска и разметка
- **Маска режет ВСЁ поддерево**: контент, фон, рамку, `box-shadow`, дочерние элементы.
  Плашка/кнопка, которая должна лежать **в вырезе**, обязана быть **сестрой** маскированного
  элемента (слой выше), а не его потомком — иначе её срежет.
- Маска — на **ограниченный блок** (фото-зона, поверхность карточки), не на страницу/секцию.
- Внутренний угол выреза считается от **угла поверхности**: плашка центрируется в вырезе,
  а не «где-то рядом».

### Геометрия и зазор
- `--r` (радиус дуги) и `--s` (глубина выреза) — **в px** (или `toEm`, если поверхность em-масштабируется),
  но **не в процентах**: маска не тянется от ширины блока.
- **Плашка меньше выреза** и по пропорциям: зазор ~6–10px по обеим сторонам.
  Пример: вырез 56–64px → кнопка 44–48px. Если плашка больше выреза — вырез не виден.
- Форма плашки: **закруглённый квадрат** (радиус 12–18) или круг — согласовывать с дугой выреза;
  прямоугольные «впритык» формы смотрятся как приклеенные.
- Плашка не должна касаться кромки выреза (нет зазора → выглядит как дефект).
- Тень/свечение плашки **не должны** выходить за карточку — иначе возможен горизонтальный скролл;
  проверять: `document.documentElement.scrollWidth > document.documentElement.clientWidth`.

### Техника
- Только **полный код генератора** (`css-shape.com/inverted-radius`): 5 слоёв + `mask-repeat: no-repeat`.
  4-слойный вариант из статьи/CodePen тайлит conic и даёт «облако».
- Код генератора — **для конкретного угла**. Ручное зеркало «на глаз» не работает
  (у каждой грани свои позиции/углы слоёв). Для других углов — второй угол получаем
  через **перевёрнутый вложенный слой** (`scaleY(-1)` + контр-переворот контента) тем же кодом,
  а не подбором координат.
- Маска **не меняет hit-area**: клики по «пустоте» выреза идут в элемент. Плашка перекрывает свою часть.
- Анимации размера/позиции маски — запрещены (пересчёт трафарета каждый кадр).

### Производительность
- Статичная маска растеризуется один раз на размер/DPR; дальше — композитинг.
- Одна маска на карточку, не складывать `mask + backdrop-filter + filter` на одном элементе.
- Держать число маскированных элементов на экран разумным (12–24 карточки в сетке — ок).
- Проверка: DevTools → Rendering → Layer borders / Paint flashing; реальный бюджетный Android.

### Стили кнопки
- Стили плашки (форма, размер, тени) — в **`UButton`** (вариант), не в scoped-стилях карточки:
  карточка задаёт только позицию слоя.

## 8. Проверка визуала и состояний компонентов (обязательно)

Появилось после реальных промахов: код «работал», но композиция была неверной.

### Перед правкой компонента — выписать его состояния
- **Все** состояния: `default`, `hover`, `focus-visible`, `disabled`, `in-cart`/`selected`, `loading`.
- **Псевдоэлементы** и их трансформации по состояниям (пример: у `add` крест «+» в корзине
  превращается в **галочку** через `::before/::after` + `rotate`; заливка зелёная, `opacity .8`).
- Не менять/заменять вариант, пока не перечислены состояния — иначе они теряются
  (так пропал `btn_add_is-added`).
- Геометрию псевдоэлементов копировать у исходного варианта (right-based и т.п.), иначе
  состояние «сломает» позиционирование.

### После изменений — проверка инструментами (не на глаз по полному скриншоту)
1. **Кроп-скриншот** изменённого элемента на 390, масштаб 2–3× (полный экран бесполезен:
   детали 40px на кадре 390 не видно).
2. **Числа**: прямоугольники (плашка vs вырез/кромка), зазоры по 4 сторонам, пропорции —
   из `getBoundingClientRect()` и вычисленных стилей, а не «на глаз».
3. **Сверка с референсом/эталоном** в том же масштабе (зазор, форма, пропорции).
4. **Гармония**: пропорционально ли, аккуратно ли, стильно/оригинально там, где это нужно.
   «Работает технически» ≠ «выглядит правильно».
5. Горизонтальный скролл: `scrollWidth == clientWidth`.
6. Только после этого — отчёт (и деплой).

### Маски на адаптивных карточках — масштабировать, не фиксировать
- Если карточка может менять ширину (сетка 1/2 колонки, мобилка/десктоп), вырез **обязан**
  масштабироваться вместе с ней: `--notch-r/--notch-s/--notch-size/--notch-gap` на карточке,
  оверрайды через `@container card (...)`. Фиксированные px годятся только для карточки
  с фиксированной шириной.
- Вырез = плашка + 2 × зазор; менять одновременно (пропорции).
- Псевдоэлементы внутри плашки — позиции и размеры **от её размера** (`calc(var(--size) * k)`),
  а не скопированные из компонента другого размера (так «плывёт» крест/галочка).

### Проверять тот же экран, что видит пользователь
- Скриншот пользователя = целевое состояние: те же вьюпорт, состояние фильтра, число колонок,
  размер карточки. Замеры в «удобном» состоянии (другая колонка/ширина) ничего не доказывают.
- Для каждого состояния проверить числа: размер карточки, вырез, плашка, зазоры, центровку «+»/галочки.

### Вырез: радиус дуги = зазору (иначе отступы неравные)
- В inverted-radius **радиус вогнутой дуги (r) должен быть равен зазору** между плашкой и кромкой.
  Тогда расстояние одинаково со всех сторон, включая внутренний угол. Если r > зазора — у внутреннего
  угла плашки зазор визуально минимальный (самый заметный дефект).
- Глубина выреза `s` = размеру плашки (тогда вырез = плашка + 2·зазор = s + 2r).
- Порог контейнерного запроса проверять по фактической ширине карточки (220 ≠ ≤210 — не забывать,
  что 1 колонка и 2 колонки дают разные ширины; порог брать с запасом, напр. ≤230).
- Скрытые элементы (напр. «ПОДРОБНЕЕ») тоже включать в контейнерный запрос — иначе они выбиваются
  из пропорций карточки. Отсутствие правила в CQ — не «не сработало», а «не написано».

### Пропорции плашки в вырезе
- Плашка ≈ **20–22%** ширины карточки (как на референсе), вырез = плашка + 2·зазор,
  r = зазору. Занижённая плашка (17%) читается как «маленькая кнопка в большом вырезе».
- Галочка «в корзине» — **робастно**: уголок из двух рамок (`border-left/bottom`) повёрнутый
  на −45°, а не две отдельные линии с голыми `transform` (последние легко «плывут»).
