# CSS mask vs SVG clip-path: честное сравнение

Контекст: вырез (вогнутый радиус) в карточке товара, 27.10.2026.
Обе дорожки с одинаковыми параметрами дали pixel-diff **1.5%** (только край/сглаживание).

| Критерий | CSS `mask` (5 слоёв) | SVG `clip-path: path()` |
|---|---|---|
| **Объём кода** | ~20 строк градиентов, смысл нечитаем | 1 путь `d` (может быть длинным), но геометрия явная |
| **Где править форму** | «магия» слоёв/позиций — на глаз | координаты в `d` — числами |
| **Доступ агента к геометрии** | нет: только визуально/трассировкой | **есть**: `getBBox`, координаты, масштаб |
| **Производительность** | растрирование маски + композитинг | векторный клип, дешевле; без растровой маски |
| **3D-переворот** | слой пересобирается → задержка появления | пересборки нет |
| **`translateZ`/промоут** | **ломает** отрисовку маски (проверено) | не влияет |
| **Отзывчивость** | px; нужны CSS-переменные + CQ | тот же `viewBox`/масштаб |
| **Кнопка в вырезе** | маска режет потомков → кнопку выносить отдельным слоем | клип не режет DOM — проще с z-index |
| **Совместимость** | `mask` — современные; старый Safari — `-webkit-` | `clip-path: path()` — современные |
| **Поддержка/баги** | готовая, массовая | зависит от точности path (нужна трассировка) |
| **Отладка** | сложно (5 слоёв) | просто (координаты) |
| **Итог** | быстрый старт, но непрозрачно | дольше на старте, дешевле и предсказуемо в работе |

## Вывод
Для **одноразовой** фигуры маска быстрее (скопировал генератор — работает).
Для **продуктовой** фигуры, которую придётся менять и комбинировать с кнопками/состояниями —
**path выигрывает**: явная геометрия, дешевле в runtime, не ломается от 3D/промоута.

Практический рецепт: маска как **эталон** → `potrace` → `path` → diff до ~0. Так получаем и точность маски, и преимущества кода.
