## Решения (27.09) — унификация «вложенного слайдера»

Согласовано 27.09, к реализации отдельным заходом (после проверки текущего варианта).

**Контекст.** Слайдер расчёта живёт внутри слайдера панели, поэтому потребовалась обвязка:
`:deep`-обходы, отключение нативного скролла, собственный свайп. Приём нужно сделать единым
инструментом, а не разовой правкой в одном компоненте.

1. **`USlider`: проп `nested`** (по умолчанию `false`, другие слайдеры не затрагиваются) —
   режим «слайдер внутри слайдера»:
   - `touch-action: pan-y` (горизонталь — слайдеру, вертикаль — родительской прокрутке);
   - `overflow-x: hidden` + `scroll-snap-type: none` у контейнера (нативный скролл не нужен,
     переход только программный — заодно уходит рывок от snap);
   - собственный свайп: `touchstart`/`touchend`, порог ~40px, проверка доминирующей оси
     (`|dx| > |dy|`), сброс по `touchcancel`, затем `go()`;
   - **не слушать `scroll` для активного слайда** (только `go()`/табы) — см. причину дёргания ниже.
2. **`USlider`: проп `pagination-clickable` — СНЯТО (28.09).** Для точек расчёта это не требуется:
   точки остаются штатными (клик/aria), отдельного «индикатора» не делаем.
3. **`HamburgerGarden` (фактическая реализация, 27–28.09):** блок расчёта — `<USlider nested>`;
   сам жест остаётся на секции расчёта (её зона шире слайдера) и вызывает `USlider.swipeBy(dx, dy)`;
   `:deep`-обходы убраны, остаётся оформление точек (размер, выравнивание вправо, цвета).
4. **Причина дёргания табов (найдена):** в `USlider` флаг `suppressScrollActive` снимается
   **по таймауту 500 мс**, а плавная прокрутка к следующему слайду может идти дольше. Тогда
   `handleScroll` считает активный слайд по промежуточному `scrollLeft`, откатывает `active`
   на предыдущий, а после завершения прокрутки ставит нужный — таб мигает назад-вперёд.
   Остаточный `scroll-snap-type: x mandatory` добавляет рывок в конце.
   Решение: в режиме `nested` не обрабатывать `scroll` вовсе; в общем случае — сбрасывать
   подавление по `scrollend`, а не по таймауту.
5. **Про CSS «чтобы не перекатывался»:** это `scroll-snap-type: x mandatory` +
   `scroll-snap-stop: always` — но они действуют только на **нативный** свайп. В режиме
   `nested` нативный скролл отключён, переход делает `go()`, поэтому эти свойства на поведение
   вложенного слайдера больше не влияют (перекат ограничивается в JS — всегда один шаг).
   Их оставляем для остальных слайдеров, где свайп нативный.

## Правки калькулятора (замечания 30.09.2026)

Замечено на слайде «Заготовки» — касается движка `CalcSection`, значит и «Посадки»:

1. **Табы режимов вылезают за пределы блока.** Ряд табов — flex без переноса, кнопки не сжимаются,
   поэтому при 4 режимах («Варенье / Консервация / Засолка / Компот») последний выходит за правый
   край. **Фикс:** перенос строк (`flex-wrap: wrap`) и/или сетка
   (`grid-template-columns: repeat(auto-fit, minmax(…))`), плюс `row-gap`.

2. **Высота блока расчёта не уменьшается по контенту.** У слайдов разное число строк (3 против 6),
   но контейнер слайдера всегда высотой по самому высокому слайду → у коротких режимов снизу пусто.
   `flex: 1 1 auto` на таблице не поможет: слайды лежат в одном flex-ряду, высота ряда определяется
   самым высоким элементом (cross-axis).

   **Варианты:**
   - **A (рекомендую):** отказаться от «слайдов» для таблиц — показывать таблицу активного режима
     (`v-if`), а свайп по секции расчёта переводить в `selectMode(следующий/предыдущий)`. Высота —
     по контенту, свайп сохраняется.
   - **B:** оставить слайдер, но задавать контейнеру высоту активного слайда
     (ResizeObserver + `transition: height`). Сложнее, риск «дёрганья».
   - **C:** косметика — убрать фон/рамку у слайда расчёта, чтобы пустота не была видна.

   **Решение:** выбрать A / B / C (реализация — после 13:00).

   **Решено (30.09):** вариант **A** — таблицу активного режима показываем напрямую (без слайдов),
   свайп переводим в переключение режима. Табы — `flex-wrap: wrap` (п. 1).

3. **Свайп только по блоку таблицы (30.09).** Сейчас жест висит на всей секции расчёта, из-за чего
   может срабатывать при действиях рядом (табы, поле). Перенести touch-обработчики на **контейнер
   таблицы/слайдера**: листание только при горизонтальном свайпе по блоку таблицы, вертикальный
   скролл сохраняется (`touch-action: pan-y`). В варианте A это тот же блок: свайп → `selectMode`.

4. **Приоритет статей по режиму (30.09).** Нужно, чтобы при выборе режима («Компот», «Варенье»…)
   статьи этого режима шли первыми в списке. Статьи привязаны к продуктам, а не к режимам, поэтому
   предлагается добавить в `Blog` поле **`mode`** (enumeration: `jam` / `canning` / `salting` /
   `compote` / пусто) и сортировать статьи на фронте: сначала совпавшие с активным режимом, затем
   остальные. Для «Посадки» это не нужно (статьи по растению). Требует: схема `Blog` + миграция,
   простановка `mode` у 6 статей, сортировка в `CalcSection` (обобщённо — через опцию конфига).
   **Подтверждено 30.09** — делаем так.

5. ~~**Модалка товара в «Заготовках»**~~ — **закрыто 30.09**: после перезагрузки страницы окно
   товара открывается (из корзины и из слайда) — это был кэш старой сборки после деплоя, кода не

## Справочно

**Модель данных (готова).** `crop`: имя, слаг, картинка, описание, `planting`, `seedling`,
`fertilizing`, `sowing`, `seo`, `category`, связи `products` и `blogs`, `isActive`.
`calculator-page`: заголовок/подзаголовок/вступление, `defaults`, `faq`, `howTo`, `seo`.
`product`: `purpose` (семена/рассада/удобрение/…), `crop`, `packaging`, `image`, `mainImage`
(`mainImage` — нелокализуемое, 24.09).

для текущих проверок допустимы примерные значения.
