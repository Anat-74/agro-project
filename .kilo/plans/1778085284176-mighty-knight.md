# Уточнённый план реализации AI-ассистента (Speed-focused MVP)

## Ключевые принципы

1. **Минимально рабочая версия (MVP)** — начинаем с простейшего, усложняем только когда нужно
2. **Скорость ответа пользователю** — каждый лишний roundtrip, токен в промпте и слой абстракции увеличивает задержку
3. **Правило последовательности** — каждый пункт выполняется только после одобрения

## Согласованные изменения относительно первой версии плана

| Пункт                 | Первая версия                                                                      | Новая версия                                                            |
| --------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **1.2** Переводы      | 4 файла (`ui.ts`, `errors.ts`, `messages.ts`, `quick-suggestions.ts`) + директория | 1 файл `chat-assistant.ts` (ru + be вместе)                             |
| **1.3** Контекст      | Map + sessionStorage + locale-поиск                                                | Простой `ref` с последним результатом поиска                            |
| **1.4** Промпт        | 100-150 строк                                                                      | 40-60 строк, без длинных примеров                                       |
| **1.5** Карточки      | Изображение + ссылка + кнопка (полная карточка)                                    | Изображение 80x80 (NuxtImg) + ссылка + кнопка "В корзину", без описания |
| **2.1** StrapiService | Создать сервис-класс                                                               | Пропустить для MVP, прямые `$fetch`/`useStrapi()`                       |
| **2.2** Кэширование   | Многоуровневое (Map + LocalStorage + sessionStorage + TTL)                         | Только встроенная дедупликация Nuxt 4                                   |
| **2.3** Ошибки        | Иерархия классов + `errors.ts`                                                     | `status`/`error` из `useAsyncData` + серверный try/catch                |

## Структура промпта AI (40-60 строк)

Вместо 700 строк и 6+ примеров:

```
1. Роль: ассистент агро-маркета, язык — русский
2. Доступные инструменты: strapi_products (search), cart_operations (add/remove/get/clear)
3. Формат вызова: tool_calls массив, arguments — JSON строка
4. Правила:
   - сначала найти товар через search, потом использовать documentId для cart
   - content должен быть пустым при вызове инструментов
   - на русском, дружелюбно, эмодзи для корзины
5. Запрещено: XML, HTML, Markdown в tool_calls
```

Без длинных примеров с documentId. DeepSeek понимает схему из `tools` параметра API. Примеры только в формате "как выглядит tool_calls массив".

## Решение проблемы двух roundtrip'ов

Текущий код делает 2 вызова к DeepSeek:

1. Первый: промпт + сообщение → AI решает какой tool вызвать
2. Второй: результат tool → AI формирует ответ

**Для MVP оставляем как есть** (DeepSeek сам решает когда вызывать tools). Это стандартный паттерн function calling. Оптимизация (1 roundtrip) — на потом, когда будет замер скорости.

#### Файл 1: `frontend/app/components/chat-assistant/VoiceInput.vue` (НОВЫЙ)

**Структура компонента:**
- Пропсы: `disabled: boolean`, `locale: string`
- Emit: `onResult(text: string)` — когда распознавание завершено
- Локальное состояние: `isListening`, `isSupported` (проверка `window.SpeechRecognition || window.webkitSpeechRecognition`), `micVisible`

**Логика:**
```typescript
// Проверка поддержки API
const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition
const isSupported = Boolean(SpeechRecognition)
if (!isSupported) { micVisible.value = false; return }

// Создание recognition
const recognition = new SpeechRecognition()
recognition.lang = props.locale === 'be' ? 'be-BY' : 'ru-RU'
recognition.interimResults = false
recognition.maxAlternatives = 1

// Обработчики
recognition.onresult = (event) => {
  const text = event.results[0][0].transcript
  emit('onResult', text)
  isListening.value = false
}
recognition.onerror = (event) => {
  if (event.error === 'not-allowed') micVisible.value = false  // навсегда
  if (event.error === 'language-not-supported') micVisible.value = false  // be не поддерживается
  isListening.value = false
}
recognition.onend = () => { isListening.value = false }
```

**Template:**
```vue
<template>
  <button
    v-if="micVisible"
    class="voice-input"
    :class="{ 'is-listening': isListening }"
    :disabled="disabled"
    @click="toggleListening"
    :aria-label="isListening ? 'Остановить запись' : 'Голосовой ввод'"
  >
    <Icon name="material-symbols:mic" />
  </button>
</template>
```

**Иконка при прослушивании:** меняется на `material-symbols:mic-off` или добавляется CSS-класс `is-listening` с пульсацией.

**Обработка ошибок:**
- `not-allowed` → `micVisible = false` (пользователь отказал в доступе, больше не показываем кнопку)
- `language-not-supported` → `micVisible = false` (браузер не поддерживает be-BY, скрываем кнопку для этой сессии)
- Остальные ошибки (no-speech, abort, network) → `isListening = false`, кнопка остаётся видимой

#### Файл 1: `frontend/server/utils/product-recommendations.ts` (НОВЫЙ)

**Функция `getRecommendations`:**
```typescript
import { $fetch } from "ofetch";

interface RecommendationResult {
  success: boolean;
  products: any[];
  total: number;
  basedOn: string;
  note?: string;
  error?: string;
}

export async function getRecommendations(
  basedOn: "category" | "latest" | "discount",
  sourceType?: string,
  sourceId?: string,
  limit: number = 5,
): Promise<RecommendationResult>
```

**Логика по режимам:**

1. **`category`** (требует `sourceId` — documentId товара):
   - Шаг 1: GET `/api/products?filters[documentId][$eq]=${sourceId}&populate=category`
   - Шаг 2: Извлечь category.documentId из ответа
   - Шаг 3: GET `/api/products?filters[category][documentId][$eq]=${categoryId}&filters[documentId][$ne]=${sourceId}&sort=createdAt:desc&pagination[pageSize]=${limit}&populate=*`
   - Если у товара нет категории → вернуть `{ success: false, note: "У товара нет категории" }`

2. **`latest`**:
   - GET `/api/products?sort=createdAt:desc&pagination[pageSize]=${limit}&populate=*`

3. **`discount`**:
   - GET `/api/products?filters[isDiscount][$eq]=true&sort=createdAt:desc&pagination[pageSize]=${limit}&populate=*`

**Обработка изображений и категорий:** такая же как в `product-search.ts` (Strapi v5 format).

**Возврат:**
```typescript
return {
```

#### Базовые правила для всего кода стилей

1. `toRem()` / `toEm()` — **0 px** в значениях

3. `@include hover` — **0 прямых `:hover`**
