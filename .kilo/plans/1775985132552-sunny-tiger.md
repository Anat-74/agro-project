# Окончательный план эффективной реализации AI-ассистента (обновленная версия)

## Архитектурное решение: Интеграция с существующей экосистемой проекта

### Выбранный подход: Использование `@nuxtjs/strapi` модуля и `useAsyncData` Nuxt 4

**Обоснование выбора:**
1. **Интеграция с проектом**: Проект уже использует `@nuxtjs/strapi` модуль и `useLocale()` для локализации через параметры маршрута `[lang]`
2. **Производительность Nuxt 4**: Использование обновленного `useAsyncData` с полной поддержкой состояний (`status`, `error`, `refresh`, `execute`)
3. **Локализация**: Полная интеграция с существующей системой локализации - все запросы включают фильтр `filters[locale][$eq]: currentLocale.value`
4. **Единый источник данных**: Все конфигурации AI-ассистента будут храниться в Strapi в content type "ai-assistant" с поддержкой i18n
5. **Оптимальное разделение**: 
   - Клиентская сторона: `useStrapi()` + `useAsyncData` для SSR и реактивности
   - Серверная сторона: `$fetch` для API endpoints и обработки AI-запросов

**Техническое обоснование:**
- **Клиентская сторона**: Используем `useStrapi()` для запросов в компонентах, `useAsyncData` для загрузки данных с SSR и полной обработкой состояний
- **Серверная сторона**: Используем `$fetch` в `chat-assistant.post.ts` для прямых запросов к Strapi API и интеграции с DeepSeek
- **Локализация**: Все запросы включают фильтр `filters[locale][$eq]: currentLocale.value` через `useLocale()` composable
- **useAsyncData Nuxt 4**: Полное использование `status`, `error`, `refresh`, `execute` для надежного UX
- **Кэширование**: Используем встроенные возможности Nuxt + дополнительное клиентское кэширование через `getCachedData` option

### Ключевой принцип реализации: Минимально рабочая версия (MVP)
**Философия**: Начинать с простейшей работающей версии, добавлять сложность только когда она действительно необходима. Сейчас главное - получить работающий ассистент с базовой функциональностью, а оптимизации и улучшения UX можно добавлять постепенно.

**Приоритеты упрощения:**
1. **Высокий приоритет (сразу)**: Упростить кэширование и обработку ошибок
2. **Средний приоритет (в процессе)**: Упростить сессионное хранилище и формирование ссылок
3. **Низкий приоритет (можно отложить)**: Упрощение конфигурации из Strapi и пагинации

```typescript

  data: assistantConfig,
  status,
  error,
  refresh
} = useAsyncData(
  `ai-assistant-config-${currentLocale.value}`,
  async () => {
    const response = await find("ai-assistant", {
      filters: { locale: { $eq: currentLocale.value } },
      populate: "*"
    })
    return response.data?.[0] || getFallbackConfig(currentLocale.value)
  },
  {
    watch: [() => currentLocale.value], // Автоматический рефреш при смене локали
    server: true, // SSR для первоначальной загрузки
    default: () => getFallbackConfig(currentLocale.value), // Fallback
    getCachedData: (key) => { // Клиентское кэширование
      if (process.client) {
        const cached = sessionStorage.getItem(key)
        return cached ? JSON.parse(cached) : null
      }
    }
  }
)

#### 1.5 Реализовать сессионное хранилище контекста с учетом локализации
**Проблема**: AI не помнит результаты поиска между сообщениями, не может выполнить "найди яблоки и добавь в корзину".
**Решение**: Ввести контекст сессии с кэшированием найденных товаров и интеграцией с локализацией.
**Действия:**
1. Создать `useChatContext.ts` composable с методами:
   - `setSearchResults(query, results, locale)` - сохранить результаты поиска с учетом локали
   - `getProductIdByName(name, locale)` - получить documentId по названию товара и локали
   - `clearContext()` - очистить контекст
2. Сохранять контекст в `sessionStorage` с ключами, включающими локаль: `chat-context-${locale}`
3. В `chat-assistant.post.ts` добавлять контекст в промпт AI с учетом локали запроса
4. Обновить промпт: объяснить AI как использовать сохраненные documentId с учетом локали

**Пример реализации:**
```typescript
// useChatContext.ts
export const useChatContext = () => {
  const { currentLocale } = useLocale()
  const context = ref<ChatContext>({
    searchResults: new Map<string, ProductSearchResult[]>(),
    lastSearchQuery: '',
    locale: currentLocale.value,
    sessionStart: new Date()
  })
  
  const saveSearchResults = (query: string, results: any[], locale: string) => {
    const key = `${locale}:${query.toLowerCase()}`
    context.value.searchResults.set(key, results)
    sessionStorage.setItem(`chat-context-${locale}`, JSON.stringify(context.value))
  }
  
  const getProductId = (productName: string, locale: string): string | null => {
    // Ищем в сохраненных результатах для данной локали
    for (const [key, results] of context.value.searchResults) {
      if (key.startsWith(`${locale}:`)) {
        const product = results.find(p => 
          p.name.toLowerCase().includes(productName.toLowerCase()))
        if (product) return product.documentId
      }
    }
    return null
  }
  
  return { context, saveSearchResults, getProductId, clearContext }
}
```

### 🟡 Приоритет 2 (важно - оптимизация и надежность)

#### 2.1 Создать StrapiService с использованием `useStrapi()` и `useAsyncData`
**Проблема**: Логика работы с Strapi разбросана, нет единого подхода к использованию `useAsyncData` Nuxt 4.
**Решение**: Единый сервис с методами, использующими `useStrapi()` и обновленный `useAsyncData` с полной поддержкой состояний.
**Действия:**
1. Создать `frontend/app/services/StrapiService.ts`
2. Реализовать методы с использованием `useStrapi()` и `useAsyncData`:
   - `searchProducts(query, locale, options)` - поиск с поддержкой локализации и полной обработкой состояний
   - `getProductById(documentId, locale)` - получение по ID с учетом локали
   - `getAssistantConfig(locale)` - конфигурация AI ассистента из Strapi
   - `getCategories(locale)` - список категорий с фильтром по локали
3. Добавить полную обработку состояний через возвращаемые значения `useAsyncData` (`status`, `error`, `refresh`, `execute`)
4. Реализовать интегрированное кэширование через `getCachedData` option `useAsyncData`

**Пример метода поиска с `useAsyncData`:**
```typescript
// StrapiService.ts
class StrapiService {
  searchProducts(query: string, locale: string, options: SearchOptions = {}) {
    const { find } = useStrapi()
    
    return useAsyncData(
      `search-products-${locale}-${query}-${JSON.stringify(options)}`,
      async () => {
        const response = await find("products", {
          filters: {
            name: { $contains: query },
            locale: { $eq: locale },
            ...options.filters
          },
          populate: options.populate || "*",
          pagination: { pageSize: options.limit || 10 },
          sort: options.sort || "name:asc"
        })
        return response
      },
      {
        server: true,
        lazy: options.lazy || false,
        getCachedData: (key) => {
          if (process.client) {
            const cached = sessionStorage.getItem(key)
            return cached ? JSON.parse(cached) : null
          }
        }
      }
    )
  }
}
```

#### 2.2 Реализовать интеллектуальное кэширование с интеграцией в `useAsyncData`
**Проблема**: Повторные одинаковые запросы нагружают Strapi, медленный ответ для пользователя.
**Решение**: Интегрированное кэширование через возможности `useAsyncData` Nuxt 4 и дополнительное клиентское кэширование.
**Действия:**
1. Расширить `StrapiService` методами кэширования:
   - `searchWithCache(query, locale, options)` - поиск с интегрированным кэшированием
   - `clearCache(locale?)` - очистка кэша с фильтрацией по локали
2. Реализовать многоуровневое кэширование:
   - **Встроенное кэширование Nuxt**: через `useAsyncData` дедупликацию и `getCachedData`
   - **Память процесса**: Map для текущей сессии, TTL 5 минут
   - **LocalStorage**: для повторных посещений, TTL 30 минут
   - **Ключ кэша**: `search:${query}:${locale}:${limit}:${JSON.stringify(filters)}`
3. Добавить инвалидацию кэша при:
   - Смене локали пользователя
   - Пользовательском действии "обновить результаты"
   - Истечении TTL
   - Изменении данных в Strapi (через webhook или manual invalidation)

**Стратегия TTL с учетом локализации:**
- Поисковые запросы: 5 минут (частые изменения цен/наличия)
- Детали товара: 1 минута (критичная актуальность)
- Категории: 30 минут (редко меняются)
- Конфигурация AI ассистента: 15 минут (может меняться через админку)
- Рекомендации: 15 минут

#### 3.1 Реализовать предикаты поиска с учетом локализации ("дешевые яблоки", "свежие овощи")
**Проблема**: Текущий поиск только по названию, нет поддержки фильтров в запросе пользователя на разных языках.
**Решение**: Расширенный поиск с анализом естественного языка и учетом локализации.
**Действия:**
1. Создать `SearchQueryParser` с поддержкой русского и белорусского языков:
   - Извлекать ключевые слова: "дешевые"/"танныя", "свежие"/"свяжыя", "органические"/"арганічныя"
   - Определять числовые значения: "до 100 руб"/"да 100 руб", "1 кг", "2-3 шт"
   - Распознавать категории на обоих языках: "фрукты"/"садавіна", "овощи"/"гародніна"

   - Цена: `filters[price][$lte]`, `filters[price][$gte]`
   - Категория: `filters[category][slug][$eq]` (с учетом локализованных slug)
   - Наличие: `filters[inStock][$eq]`
   - Теги: `filters[tags][name][$eq]` (если есть в Strapi)
3. Добавить инструмент `advanced_search` для AI с поддержкой фильтров и параметром locale

### Что можно упростить без ущерба функциональности:

1. **Стратегия кэширования**
   - **Текущий план**: Многоуровневое кэширование (Nuxt встроенное, память процесса, LocalStorage) с разными TTL
   - **Упрощение**: Использовать только встроенное кэширование Nuxt через `useAsyncData` + простой `sessionStorage` для текущей сессии. Убрать сложную логику TTL и инвалидации.

2. **Обработка изображений**
   - **Текущий план**: `mainImage` → заглушка (уже упрощено)
   - **Дополнительное упрощение**: Не обрабатывать разные форматы изображений (thumbnail, small, medium). Использовать оригинальное изображение и полагаться на оптимизацию `NuxtImg`.

3. **Система ошибок**
   - **Текущий план**: `ChatError` класс с типами ошибок и сложной системой локализации
   - **Упрощение**: Использовать простые строковые коды ошибок и lookup в файлах переводов. Убрать иерархию классов ошибок.

4. **Сессионное хранилище контекста**
   - **Текущий план**: Сложная структура с Map, сохранением в sessionStorage, поиском по локали
   - **Упрощение**: Хранить только последние результаты поиска для текущей локали в простом объекте. Не реализовывать сложный поиск по историческим результатам.

5. **Формирование ссылок на товары**
   - **Текущий план**: Адаптация серверной логики аналогично клиентскому `useProductLink()` с учетом иерархии категорий
   - **Упрощение**: Использовать простой шаблон ссылки `/${locale}/products/${product.slug}` если такая структура существует, или вообще не формировать ссылки на сервере, а передавать slug и формировать ссылку на клиенте.

6. **Конфигурация AI из Strapi**
   - **Текущий план**: Content type с компонентами для welcomeMessage, quickSuggestions, aiPersonality
   - **Упрощение**: Хранить только текстовые поля (welcomeTitle, welcomeText, quickSuggestions как JSON). Убрать компоненты для большей простоты.

7. **Пагинация результатов в чате**
   - **Текущий план**: Поддержка hasMore и сложной пагинации
   - **Упрощение**: Показывать только первые 5-10 товаров с простой кнопкой "Показать еще", которая делает новый запрос с увеличенным лимитом.

8. **Резервные конфигурации (fallback)**
   - **Текущий план**: `getFallbackConfig()` функция с полной конфигурацией
