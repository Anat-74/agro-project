# План решения проблем AI-ассистента

## Проблемы

### 1. Ошибка LangSwitcher при SSR
**Симптомы**: При запросе к AI-ассистенту возникает ошибка:
```
Cannot read properties of undefined (reading 'ariaLabelLang')
at LangSwitcher.vue:43:69
```

**Причина**: Компонент `LangSwitcher.vue` использует `buttonTranslations[currentLocale].ariaLabelLang`, где `currentLocale` может иметь значение, не входящее в допустимые ('ru' | 'be'). В файле `button.ts` определены только переводы для 'ru' и 'be'.

**Коренная причина**: Хук `useLocale` может установить `currentLocale` в недопустимое значение при инициализации, если `route.params.lang` содержит невалидный код языка (например, 'en').

### 2. Ошибка MCP API 500
**Симптомы**: При вызове AI-ассистента для поиска товаров возникает ошибка:
```
❌ Ошибка поиска: MCP API error: 500 Server Error
```

**Причина**: Endpoint `/api/mcp/tools` либо не существует, либо MCP сервер не запущен/неправильно настроен.

**Контекст**:
- В `useChatMCP.ts` делается запрос к `/api/mcp/tools`
- В структуре проекта нет файла `server/api/mcp/tools.ts`
- MCP инструменты должны быть настроены через MCP сервер (Strapi MCP)

### 3. Связь между быстрыми предложениями и ошибкой LangSwitcher
**Цепочка событий:**
1. Пользователь нажимает "Найди яблоко" (быстрое предложение)
2. Вызывается `sendQuickMessage('Найди яблоко')`
3. `getQuickSuggestionInstruction` возвращает `{type: 'search_products', data: {query: 'яблоко'}}`
4. Вызывается `chatCart.executeCartAction(instruction, callMCPTool)`
5. В `useChatCart.ts` для `type: 'search_products'` вызывается `callMCPTool('search_products', {...})`
6. `useChatMCP.ts` делает POST запрос к `/api/mcp/tools`
7. Endpoint `/api/mcp/tools` не существует → возвращается 500 ошибка
8. Nuxt пытается отрендерить страницу ошибки (SSR)
9. Во время SSR рендеринга страницы ошибки рендерится компонент `LangSwitcher` (часть layout)
10. `LangSwitcher` вызывает `buttonTranslations[currentLocale].ariaLabelLang`
11. `currentLocale` имеет недопустимое значение (undefined, пустая строка или не 'ru'/'be')
12. Возникает ошибка: `Cannot read properties of undefined (reading 'ariaLabelLang')`

**Коренные причины:**
1. Endpoint `/api/mcp/tools` не реализован
2. Быстрые предложения используют устаревший механизм `clientInstruction` вместо основного AI pipeline
3. `useLocale` не валидирует `currentLocale` при инициализации
4. `LangSwitcher` не защищен от недопустимых значений `currentLocale`

## План решения

### Фаза 1: Исправить LangSwitcher (срочно)
1. **Защита от undefined в LangSwitcher**
   - Добавить проверку существования `buttonTranslations[currentLocale]`
   - Использовать fallback на 'ru' если перевод отсутствует
   - Или исправить `useLocale` чтобы гарантировать валидный LocaleCode

2. **Исправить инициализацию useLocale**
   - Добавить валидацию при установке `_currentLocale` в начальном значении
   - Гарантировать, что `currentLocale` всегда имеет допустимое значение ('ru' или 'be')

### Фаза 2: Исправить логику быстрых предложений
1. **Заменить `sendQuickMessage` на отправку обычных сообщений**
   - Изменить `sendQuickMessage` чтобы вызывать `handleSendMessage(message)` вместо `executeCartAction`
   - Это обеспечит обработку через основной AI pipeline с использованием `strapi_products` инструмента

2. **Упростить или удалить `getQuickSuggestionInstruction`**
   - Убрать логику создания `clientInstruction` для быстрых предложений
   - Быстрые предложения будут отправлять текстовые сообщения, которые AI обработает через стандартные инструменты

3. **Обновить быстрые предложения для работы с AI pipeline**
   - "Найди яблоко" → отправит текст "найди яблоко" через `handleSendMessage`
   - "Найди овощи" → отправит текст "найди овощи"
   - "Добавь картофель" → отправит текст "добавь картофель в корзину"
   - Это обеспечит использование `strapi_products` и `cart_operations` инструментов через AI

### Фаза 3: Реализовать MCP API endpoint (опционально)
1. **Создать endpoint `/api/mcp/tools`**
   - Файл: `server/api/mcp/tools.post.ts`
   - Реализовать совместимость с JSON-RPC 2.0 для MCP инструментов
   - Интегрировать с Strapi MCP сервером

2. **Альтернатива: исправить useChatCart**
   - Изменить вызов callMCPTool('search_products', ...) на прямой вызов strapi_products
   - Использовать существующий механизм поиска из chat-assistant API

### Фаза 3: Тестирование
1. **Проверить LangSwitcher** с разными значениями `route.params.lang`
2. **Протестировать AI-ассистент** с поиском товаров
3. **Убедиться**, что добавление в корзину работает для составных запросов

### Исправление LangSwitcher.vue
```vue
<script setup>
import { buttonTranslations } from '~/locales/button'

const { currentLocale, locales, switchLocale } = useLocale()

// Безопасный доступ к переводам
const getButtonTranslation = (locale: string) => {
  return buttonTranslations[locale as keyof typeof buttonTranslations] || buttonTranslations.ru
}
</script>

<template>
  <div class="lang-switcher">
    <UButton
      v-for="locale in locales"
      @click="switchLocale(locale.code)"
      variant="lang-switcher"
      :key="locale.code"
      :icon="locale.icon"
      :class="{ active: currentLocale === locale.code }"
      :aria-label="getButtonTranslation(currentLocale).ariaLabelLang"
     />
  </div>
</template>
```

### Исправление useLocale.ts
```typescript
const _currentLocale = ref<LocaleCode>(
  (() => {
    // Безопасное получение языка из route.params (может быть undefined в некоторых контекстах)
    const routeLang = route.params?.lang as string | undefined
    const cookieLang = langCookie.value
    const lang = routeLang || cookieLang || 'ru'
    
    // Валидация: только 'ru' или 'be'
    const validLang = ['ru', 'be'].includes(lang) ? lang : 'ru'
    return validLang as LocaleCode
  })()
)

// Также можно добавить защиту в computed setter
const currentLocale = computed({
  get: () => _currentLocale.value,
  set: (value: LocaleCode) => {
    // Валидация перед установкой
    const validValue = ['ru', 'be'].includes(value) ? value : 'ru'
    _currentLocale.value = validValue as LocaleCode
    langCookie.value = validValue
    if (route.params.lang !== validValue) {
     router.replace({
        params: { ...route.params, lang: validValue },
        query: route.query
      })
    }
  }
})
```

### Создание MCP API endpoint (опционально)
```typescript
// server/api/mcp/tools.post.ts
import { defineEventHandler, readBody } from 'h3'
import { searchProducts } from '../utils/product-search'

export default defineEventHandler(async (event) => {
  try {
    const body = await readBody(event)
    
    // Валидация JSON-RPC 2.0 запроса
    if (body.jsonrpc !== '2.0') {
      throw new Error('Invalid JSON-RPC version')
    }
    
    const { method, params, id } = body
    
    // Обработка инструментов
    if (method === 'tools/call') {
      const { name, arguments: args } = params
      
      // Вызов соответствующего инструмента
      let result
      if (name === 'strapi_products' || name === 'search_products') {
        const { operation, query, category, limit } = args
        if (operation === 'search' && query) {
          result = await searchProducts(query, category, limit)
        } else {
          result = {
            success: false,
            error: `Операция ${operation} не поддерживается`
          }
        }
      } else if (name === 'cart_operations') {
        // Простая реализация операций с корзиной
        result = {
          success: true,
          message: `Операция ${args.operation} выполнена`,
          operation: args.operation,
          productId: args.productId,
          quantity: args.quantity
        }
      } else {
        throw new Error(`Unknown tool: ${name}`)
      }
      
      return {
        jsonrpc: '2.0',
        result,
        id
      }
    }
    
    throw new Error(`Unknown method: ${method}`)
  } catch (error) {
    return {
      jsonrpc: '2.0',
      error: {
        code: -32603,
        message: error instanceof Error ? error.message : 'Internal error'
      },
      id: body?.id || null
    }
  }
})
```

## Приоритеты
1. **Критический**: Исправить LangSwitcher - блокирует SSR рендеринг при любой ошибке (включая 500 от API)
2. **Высокий**: Исправить быстрые предложения - устраняет причину обращения к несуществующему MCP API
3. **Средний**: Реализовать MCP API endpoint - для полноценной работы MCP инструментов (может быть отложено)
4. **Низкий**: Улучшить обработку ошибок в AI-ассистенте

## Оценка времени
- Исправление LangSwitcher: 15-30 минут (включая валидацию в useLocale)
- Исправление быстрых предложений: 15-30 минут (изменение sendQuickMessage)
- Создание MCP API endpoint: 30-60 минут (можно отложить, если быстрые предложения будут работать через AI pipeline)
- Тестирование: 15-30 минут

## Последовательность действий
1. **Исправить LangSwitcher** - предотвратит ошибку при любом SSR рендеринге, включая страницы ошибок
   - Добавить защиту в `LangSwitcher.vue` от недопустимых `currentLocale`
   - Валидировать `currentLocale` в `useLocale.ts` при инициализации

2. **Исправить быстрые предложения** - перенаправит поиск через рабочий AI pipeline
   - Изменить `sendQuickMessage` для отправки текстовых сообщений через `handleSendMessage`
   - Убрать зависимость от `callMCPTool('search_products')`
   - Использовать существующий `strapi_products` инструмент через AI

3. **Реализовать MCP API** (опционально) - для поддержки других MCP инструментов
   - Создать `server/api/mcp/tools.post.ts` с JSON-RPC 2.0
   - Или отложить, если функциональность поиска работает через AI pipeline

**Важно**: После шагов 1 и 2 поиск товаров через быстрые предложения должен работать корректно через основной AI pipeline, и ошибка LangSwitcher больше не будет возникать.

## Риски
1. MCP сервер Strapi может требовать дополнительной настройки
2. Могут потребоваться изменения в настройках CORS
