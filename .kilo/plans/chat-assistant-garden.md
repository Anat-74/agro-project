# План: чат-ассистент в разделах «Посадка» и «Заготовки»

> **Режим:** удалённая работа; реализация — **в непиковые часы** (7–9 и 13–4 МСК).
> Зафиксировано 28.09.2026. Связанное: `agro-calculator.md` (раздел «Посадка», п. 7),
> `preserves-section.md` (раздел «Заготовки»), `frontend/docs/ai-assistant*.md` (устройство ассистента).

## Цель и приоритет

Ассистент в разделах — **консультант с источниками**, а не второй калькулятор.
Приоритет (согласовано 28.09): **консультировать** по выращиванию/хранению/заготовкам, опираясь
на материалы проекта; расчёт — задача калькулятора (он простой и с ним справляются).

## Решения (28.09)

### 1. Общие знания — гибрид с приоритетом материалов (вариант B)

1. Сначала **поиск по материалам проекта** → ответ + ссылки.
2. Если материалов нет — ответ по общим агро-знаниям **с явной пометкой** («в наших материалах этого
   нет; по общим рекомендациям…») и **дисклеймером**: «рекомендации справочные, точные нормы — в
   калькуляторе раздела».
3. **Числа — только из Strapi.** Любые нормы/дозировки (сахар, соль, уксус, удобрения, всхожесть,
   г/м² и т. п.) модель не придумывает — отправляет пользователя в калькулятор/раздел.
4. **«Опасные» темы** (пестициды, обработка химией, дозировки препаратов) — только из наших
   материалов; если их нет — прямо сообщить и направить в раздел/к специалисту.

### 2. Источники в ответе — блок «Источники» (вариант B)

- Под ответом — список **1–3 ссылок** с локализованным названием материала (без дублей).
- Формат ответа API: `{ message, sources: [{ title, url }], basis: "project" | "general" }`;
  `sources` сохраняются в истории чата и рендерятся списком в `ChatAssistant.vue`.
- Ответ из общих знаний → вместо источников пометка «Ответ по общим рекомендациям» + ссылка
  на раздел/калькулятор.
- **Не подставлять ссылки «для галочки»;** если пользователь уже на странице статьи — эта статья
  в источниках не дублируется.
- Переход по ссылке — обычный `NuxtLink` (SPA).

### 3. Контекст раздела — поэтапно

- **Этап 1 (согласовано):** в запрос передаём `section` (посадка/заготовки) и выбранный элемент
  (культура `crop` / продукт `preserve`). Тогда «как его сажать?» сразу попадает в нужные статьи.
- **Этап 2 (позже):** площадь и активный режим («а на 5 соток?», «а в граммах?»). Сложность —
  синхронизация при свайпах/смене режима, поэтому не в первой итерации.

## Инструмент поиска по контенту

- **`content_search`** (рабочее имя): полнотекстовый поиск по статьям блога (в т. ч. связанным через
  `blog.crops`), FAQ (`calculator-page.faq` / `preserve-page.faq`), шагам howTo, описаниям культур
  (`crop`) и продуктов (`preserve`).
- Реализация: REST Strapi с `$containsi` (по образцу `server/utils/product-search.ts`) — векторная
  БД на текущем объёме не нужна.
- Возврат: **3–5 лучших фрагментов** с `title`, `url`, короткой выдержкой — их LLM использует
  как опору, а `sources` формируются из них.
- Индексирование/кэш на первом этапе не делаем (контента мало).

## Точки входа

1. Панель раздела (слайд «Посадка», позже «Заготовки») — кнопка «Спросить AI», передаёт контекст
   (`section` + выбранный элемент).
2. Страница статьи — вопрос по текущей статье (контекст: сама статья).
3. Существующие точки (каталог, корзина, доставка) — без изменений.

## Порядок работ

1. Инструмент `content_search` + правила промпта (приоритет материалов, числа только из Strapi,
   «опасные» темы, формат `basis`/`sources`).
2. Формат ответа и рендер «Источники» в `ChatAssistant.vue` (+ сохранение в истории).
3. Точка входа из раздела: кнопка + передача `section`/элемента.
4. Этап 2 контекста (площадь/режим) — по необходимости.
5. «Заготовки» — те же правила, после появления раздела.

## Не-цели

- Не дублировать калькулятор в чате (кроме, при желании, подстановки уже показанного расчёта
  в текст ответа, чтобы не противоречить UI).
- Не выдумывать нормы/состав/наличие товаров: данные о продуктах — только из Strapi.
