# Стандарты стилизации проекта Agro-Market

## 1. Стек и принципы

- **Стек:** Nuxt 4, Vue 3, TypeScript, SCSS, BEM, Strapi v5.
- **Современный CSS-стек — только фичи с базовой поддержкой:** `<dialog>`, `@container` (inline-size), `@container style()`, `subgrid`, `:has()`, anchor positioning, `popover`, `@starting-style`, `:where()`. Bleeding-edge (anchor Level 2, `@container anchored`) — **не использовать**.
- **Минимум JS:** показ/скрытие, позиционирование, закрытие по Escape/клику вне, адаптив — решать нативными HTML/CSS-средствами (popover, dialog, `:has`, details), а не слушателями и `getBoundingClientRect()`.
- **Минимум обёрток (`div`):** grid + `:has()` + container queries позволяют в большинстве случаев позиционировать без лишних обёрток. Не оборачивать без необходимости. Семантические теги (`header`, `main`, `footer`, `section`, `nav`) — вместо `div`.
- **Данные:** из Strapi через `useAsyncData`/`useFetch`. Клиентские запросы — `server: false`; некритичные — `lazy: true`.

## 2. SCSS-подключение

Глобально через `vite.css.preprocessorOptions.scss.additionalData` (`nuxt.config.ts`) подключаются ТОЛЬКО `foundation/*` — в компонентах они доступны без `@use`:

```scss
@use "@/assets/scss/foundation/_settings.scss" as *;   // брейкпоинты, контейнер
@use "@/assets/scss/foundation/_functions.scss" as *;  // toRem, toEm
@use "@/assets/scss/foundation/_mixins.scss" as *;     // миксины
```

`base/*` (`_normalize.scss`, `_globals.scss`, `_utils.scss`, `_animations.scss`) подключаются один раз через `styles.scss` (css-entry) — в компонентах не импортируются.

## 3. Функции

- `toRem($px)` — вместо px. `padding: toRem(16)`.
- `toEm($px, $current: 16)` — em-размеры, брейкпоинты.

## 4. Миксины (все `@include` — ПОСЛЕ CSS-свойств, перед вложенными селекторами)

- `adaptiveValue(property, startSize, minSize)` — clamp() по вьюпорту. `@include adaptiveValue("font-size", 16, 14);`
  Полная сигнатура: `adaptiveValue(property, startSize, minSize, keepSize: 0, widthFrom: $containerWidth, widthTo: $minWidth)`:
  - `keepSize` (0–3) — какие фиксированные правила пропустить: `1` — оба края (только clamp-диапазон), `2` — без фиксации минимума, `3` — без фиксации максимума;
  - `widthFrom`/`widthTo` — собственный диапазон вьюпорта адаптива (по умолчанию `$containerWidth` → `$minWidth`). Пример: адаптив ширины 302→194 только в диапазоне планшет–десктоп, ниже 1023.98px — фикс 194px: `@include adaptiveValue("width", 302, 194, 0, $containerWidth, 1023.98);`
- `hover` — вместо прямого `:hover` (`@media (any-hover: hover)`). Прямой `:hover` не использовать.
- `containerParent(name, type)` — `container: name / inline-size`.
- `containerAdaptive(property, start, min)` — адаптив от ширины контейнера (cqw) с viewport-fallback.
- `gridCards(type, min, max, gap)` — `repeat(auto-fit, minmax(min, max))`.
- `colorMix($property, $base-color, $mix-color, $ratio)` — тонирование через `color-mix(in srgb, ...)`. `$ratio: null` (default) — доля от `--brightness`.
- `maskEdgeCut($size, $side)` — диагональный срез края плашки через CSS-маску (база + треугольник, `mask-composite: subtract`). `$side`: `"bottom-right"` (default) / `"bottom-left"` / `"top-right"` / `"top-left"`. Пример: `@include maskEdgeCut(toRem(8), "bottom-left");` Подробности — раздел 18.

## 10. Grid + Container Queries

- Вёрстка преимущественно на CSS Grid (не flex-цепочки из обёрток).
- Сложные блоки (большой footer) — `grid-template-areas`.
- `> * { min-width: 0 }` — на grid-родителях.
- Subgrid: `grid-template-columns: subgrid`.
- Container Queries: `@include containerParent(name, inline-size)` + `@container name (max-width: ...)`. Адаптив от ширины БЛОКА — container queries, от вьюпорта — `@media`.

## 11. @container style() — стилевые запросы

Применение стилей от CSS-переменных на родителе:

- `style(--locale: be|ru)` — типографика под язык (h1–h4: be → Open Sans + letter-spacing)
- `style(--theme: custom)` — анимации только в custom-теме
- `style(--browser-safari: 1)` — браузерные фиксы

НЕ использовать для: яркости фона (`colorMix()`), адаптива (`@media`/`@container` inline-size), детекта возможностей (`@supports`).

## 13. `<dialog>` — блокирующие модалки (паттерн `ShowModal*` / `Show*`)

- Папка `components/show-modal/`, импорт явный.
- `useDialog(id, dialogRef, { useShowMethod })`:

| `useShowMethod` | Метод | Поведение |
|---|---|---|
| `false` (default) | `showModal()` | нативный backdrop + `::backdrop`, Escape нативно, body-lock |
| `true` | `show()` | без backdrop, Escape вручную, body-lock НЕТ |

- Конвенция имён: `ShowModal*` — `showModal()`, `Show*` — `show()`.
- Close on backdrop: `if (e.target === storedElement) close()` → внутри `<dialog>` всегда items-обёртка (панель).
- Body-lock в `_globals.scss`: `body:has(.dialog-hamburger[open], ...)` → при добавлении нового диалога добавить его класс в этот селектор.
- Анимация: `@starting-style` + `transition` с `allow-discrete` на `display`/`overlay`; позиционирование через `translate`/`margin-inline-start`.
- Родитель управляет через `defineExpose({ open, close, isOpen })` + `useTemplateRef`.

## 14. Поповеры/меню/тултипы — Anchor Positioning + Popover API (стандарт)

**Применять для новых:** дропдауны у кнопки (MoreMenu), тултипы, поповеры у ссылок, меню с автопереворотом.
**НЕ применять:** модалки на весь экран/по центру (это `<dialog>`, раздел 13); обычная вёрстка в потоке.

```html
<UButton variant="plain" class="more-menu__trigger" popovertarget="menu">Меню</UButton>
<div popover id="menu" class="more-menu__dropdown">…</div>
```

```scss
.more-menu {
  &__trigger {
    anchor-name: --more-menu;              // якорю даём имя
  }

  &__dropdown {
    position: fixed;                       // popover = top-layer
    margin: 0;
    inset: auto;
    position-anchor: --more-menu;          // цель привязывается
    position-area: bottom span-right;      // сетка 3×3, + span-* для растягивания
    margin-block-start: toRem(4);
    position-try-fallbacks: flip-block;    // автопереворот при нехватке места
  }
}
```

- Триггер — `<UButton variant="plain" popovertarget="...">`, НЕ `<button>` (см. раздел 17, п.5); `variant="plain"` — плоская кнопка без заливки
- **Каталог поповеров:** `components/popover/` (аналог `components/show-modal/` для диалогов); композабл — `usePopover(id, popoverRef)` из `composables/usePopover.ts` (аналог `useDialog`). Поповеры с общим глобальным состоянием видимости — через provide/inject (как `isContacts` в app.vue), а не локальные слушатели.
- **Hover-поповеры** (`popover="manual"`): закрытие только уходом мыши. Мост между триггером и дропдауном: поповер — DOM-потомок триггера + `::before` с `top: -gap`, продолжающий хит-зону вверх (иначе при переходе со ссылки на дропдаун сработает mouseleave и дропдаун закроется). Скрытие на мобильном — `@media { display: none }` (showPopover игнорируется, без ошибок — `usePopover.open()` в try/catch).

- Popover API: открытие/закрытие кликом, Escape, кликом вне — **без JS**. `popover="manual"` — без авто-закрытия (hover-поповеры).
- Top-layer: не нужны `z-index` и борьба с `overflow: hidden` у родителей.
- Для не-popover элементов (в потоке): `position: absolute` + `position-area`.
- Кастомный переворот: `@position-try --name { ... }` + `position-try-fallbacks: --name`.
- Анимация: fade — `@starting-style` + `allow-discrete`; высота — `height: 0→auto` + `interpolate-size: allow-keywords` (наследуется; Chrome/Edge/Opera, в FF/Safari без анимации высоты — progressive enhancement). ВАЖНО: самому `[popover]` `display` задавать нельзя (перебьёт UA-скрытие `[popover]:not(:popover-open)`) — `height`-анимацию делать на ВНУТРЕННЕМ элементе (карточке), не на поповере
- **`position-area` и переполнение:** `right`/`center` ставят поповер ПРАВЕЕ якоря, `span-left` — правым краем к правому краю якоря (расширение влево). Если поповер выходит за вьюпорт — браузер ЗАЖИМАЕТ его в скролл-порт (правый край смещается к краю экрана), и выравнивание ломается. Для меню у правого края экрана использовать `bottom span-left`, у левого — `bottom span-right`
- **Неякорные поповеры** (по центру/углу экрана, ColorMode): `position: fixed; top: 0; inset-inline: 0; margin-inline: auto; width: fit-content` (центр) — `display` на `[popover]` по-прежнему нельзя, карточка внутри. При нескольких экземплярах на странице — уникальный id через `useId()` (проп `popupId` + `usePopover(popupId, ...)`)
- Старые браузеры: прогрессивное улучшение — базовое absolute-позиционирование оставить, anchor добавлять поверх.

## 18. CSS-маски (mask / mask-composite)

Сложные фигуры UI (карточки с угловым вырезом, ноуты, скошенные углы) — чистый CSS, без SVG, лишних `div` и `overflow: hidden`-хаков.

- **Маски читают ALPHA, а не цвет:** градиент от красного к прозрачному маскирует так же, как от белого к прозрачному.
- `mask-image`: градиенты/`url()`; слои через запятую; геометрия как у `background` (`mask-size`, `mask-position`, `mask-repeat`, `mask-clip`).
- `mask-composite` — логические операторы над слоями (мысленная модель — две перекрывающиеся окружности), слои комбинируются СНИЗУ вверх:

| Оператор | Результат |
|---|---|
| `add` | объединение (по умолчанию) |
| `subtract` | вычитание — текущий слой вырезает из нижележащего |
| `intersect` | пересечение (только общая часть) |
| `exclude` | XOR — непересекающиеся части |

- **Анимация:** ключевые слова дискретны → при ховере мгновенный переход вместо анимации. Лечится `@property`: зарегистрировать свою переменную с `syntax: "<number>"`/`<length>` — она становится интерполируемой и плавно тянет значения маски.
- **Поддержка:** Baseline 2023 (Chrome/Edge 120+, Firefox 53+, Safari 15.4+).
- **Ловушка WebKit:** legacy `-webkit-mask-composite` использует ДРУГИЕ ключевые слова (`source-over`, `source-in`, `source-atop`…) — смешивать со стандартными `add/subtract/…` нельзя, WebKit молча ничего не сделает.
- `mask` vs `clip-path`: clip-path обрезает клики и только жёсткие грани; mask — градиенты/мягкие края, но, как правило, НЕ влияет на хит-тестинг (учитывать, если нужны клики только по видимой области).

### Пример: скос края «как у чека» (реализован в OrderForm)

Использовать миксин `maskEdgeCut($size, $side)` (раздел 4) — рабочий паттерн база + треугольник:

```scss
&__title {
  @include maskEdgeCut(toRem(8), "bottom-right");   // скос нижнего края
}
&__submit-wrapper {
  @include maskEdgeCut(toRem(8), "top-left");       // скос верхнего края (зеркально)
}
```

Правила маски (что в миксине):
- Слои: слой 1 (ВЕРХНИЙ) — база (`linear-gradient(#000 0 0)`), слой 2 — треугольник. `mask-composite: subtract` = «верхний минус нижележащие» → база − треугольник = срез края.
- `mask-size: 100% 100%, 100% $size` (полоса по краю), `mask-position` по углу.

ВАЖНО:
- **НЕ использовать `conic-gradient` для среза с length-стопами** (`transparent 0 8px`) — у конусного градиента стопы принимают только углы/проценты (`<angle-percentage>`), длина невалидна → объявление отбрасывается (маски нет).
- **НЕ использовать `calc(100% - Npx)`** от конца градиентной линии для `to <corner>` на прямоугольниках: конец линии лежит за углом бокса, вырез не виден.
- Для видимости среза фон плашки должен контрастировать с фоном под ней (иначе вырез «теряется»).
- Размер среза должен быть меньше вертикальных отступов контента (`padding-block`), чтобы не обрезать текст.

## 19. sibling-index() / sibling-count()

CSS-функции позиции/количества сиблингов (CSS Values 5) — замена цепочек `:nth-child()` и JS-stagger (GSAP):

- `sibling-index()` — позиция среди сиблингов (1-based, первый потомок = 1);
- `sibling-count()` — общее число сиблингов;
- возвращают целые числа и используются прямо в `calc()` — без JS и ручных CSS-переменных.

Кейсы:
- шахматный порядок: `margin-block-start: calc((sibling-index() mod 2) * toRem(12));`
- stagger-анимации: `animation-delay: calc(sibling-index() * 60ms);`
- масштабирование от количества: `width: calc(100% / sibling-count());`
- фиксированная общая длительность на N элементов: `animation-duration: calc(0.4s / sibling-count());`

**Поддержка:** Chrome/Edge 138+, Safari 26.2+, Firefox 154+ (~79.6% глобально).

**Fallback:** для декоративных эффектов (stagger) НЕ нужен — невалидное объявление отбрасывается каскадом (задержка 0, graceful degradation). `@supports` — только если фича «несущая» (без неё ломается layout).

**Нюанс Shadow DOM:** сиблинги считаются во flattened tree; со slot-элементами поведение проверять.

**Реализовано:** SaleProductsSection — каскадный вход карточек при скролле (custom-тема, десктоп ≥ `$mobile`): `animation-timeline: view()` + `animation-delay: calc(sibling-index() * 60ms)` на `:deep(.sale-products__card-list > *)`. Мобильный (`< $mobile`) — свой `scroll-animate` в DiscountProduct. Вход «всей секции при загрузке» не используем — блок ниже первого экрана, анимация не видна.
