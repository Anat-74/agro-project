## Текущее состояние (mobile, фильтр ОТКРЫТ)

- **Панель фильтров** — `position: fixed` (независима от скролла карточек):
  - `top: var(--crumb-h)` (сразу под липкими крошками), `left: toRem(5)` (= контейнерный padding-inline),
    `width: var(--filter-drawer-w)` (165px), `height: calc(100dvh − var(--crumb-h) − toRem(4))` —
    **постоянная** (без ресайза/дёрганья), свой внутренний скролл (у диалога `overflow: hidden auto`),
    фон `var(--bg)`.
  - **Шапка панели** (`.shop-filters__header`): крестик **слева**, селект сортировки **справа** — **не sticky**
    (скроллится с содержимым). На desktop скрыта (там сортировка/кнопка в тулбаре).
- **Шапка сайта** — `display: none` (AppHeader `_filter-open`, mobile): «дыры» нет, сдвигов не требуется.
- **Крошки** (шапка страницы `.products-page__header`) — `position: sticky; top: 0`, `margin-block-end: 0`.
- **Тулбар** страницы (`.products-page__container-top`) — `display: none` (его контролы — в шапке панели).
- **Товары** — 1 колонка, сдвинуты вправо: `padding-inline-start: calc(toRem(7) + var(--filter-drawer-w))`
  (контент начинается на 172px, правый край панели 170 → зазор 2px); у списка базовый
  `padding-block-end: 64px` (резерв), `overflow-x: clip`.
- **Пагинация** — absolute в `container-body`; при открытом `bottom: toRem(-63)` → её низ в **2px** от низа
  документа (`padding-block-end` секции `65px`). Зазор «последняя карточка → пагинация» ≈ **73px**.
- **Декоративный разделитель (12.10):** в зоне резерва между последней карточкой и пагинацией —
  линия + иконка-росток (`mdi:sprout`), по ширине товарной колонки, **смещён ниже центра** зазора.
  - Разметка: `<li class="products-page__divider" aria-hidden="true">` внутри `ul` (декор; `v-if="pageCount > 1"`).
  - Стили: `.products-page__card-list { position: relative }`; `&__divider { display: none }` (десктоп/закрыт);
    на mobile при `_filter-open` — `display: flex; align-items: center; position: absolute;
    inset-inline: 0; bottom: toRem(-33); height: toRem(73); padding-inline: toRem(10)` (бокс 73px,
    опускается вместе с пагинацией; `padding-inline` — отступ от краёв колонки, чтобы были видны
    закруглённые концы). Иконка `--green-color`, `font-size: toRem(43)`.
    Линии `::before/::after`: `height: toRem(2)`, `border-radius: toRem(25)`, «вдавленный» эффект —
    `background: rgba(0,0,0,0.28)` + `box-shadow: 0 toRem(1) 0 rgba(255,255,255,0.7)`. `pointer-events: none`.
  - ⚠️ **Грабли (12.10):** размер иконки задавать НА САМОМ `svg` (`svg { font-size: toRem(30) }`), а НЕ на обёртке:

  - **Ревью 12.10:** иконка реально 25px (`.iconify`) → 30 → 35 → **40px** (+5px, через `svg`); разделитель

## Кэш и «старое» после деплоя (PWA/SSR) — разбор 15.10

### Симптомы (жалобы)
1. После деплоя пользователь **перезагружал страницу** → видел свежие изменения (всё ок).
2. Через время при **возврате в приложение** (без reload) → снова **старое**, в т.ч. «фильтры цены не работают»;
   помогала **только перезагрузка страницы**.
3. Дополнительно (отдельная причина, уже исправлена): «после перезагрузки на ≥14 товары появляются,
   после переключения — снова пусто» — это была **гонка сброса страницы** (см. Ревью 14.10), не кэш.

### Почему так (слои, от простого к глубокому)
- **Слой 0 — что даёт reload.** Reload = новый документ: HTML из сети, JS с новыми хэшами, **новый JS-контекст**
  (сброс in-memory кэша `useCachedAsyncData`, Pinia и пр.). Поэтому reload всегда «лечит».
- **Слой 1 — resume PWA из памяти (главный).** ОС держит установленную PWA (и фон-вкладки) в памяти; при
  «заходе обратно» часто восстанавливается **живой процесс** — без запроса за HTML/JS. Если эта копия открыта
  до деплоя, приложение продолжает крутить **старый бандл** и свой старый in-memory кэш. Reload — единственное,
  что пересоздаёт документ.
- **Слой 2 — service worker отдавал старый HTML.** Замер `sw.js` прода: навигации `NetworkFirst`,
  `networkTimeoutSeconds: 8`, кэш `pages` (`maxAgeSeconds: 3600`, `maxEntries: 50`). Холодный старт (пробуждение
  радио, DNS/TLS, холодный Passenger) часто дольше 8 с → SW отдаёт закэшированный HTML со **старым бандлом и
  payload**. Нюанс: на таймаут-ветке запись свежего HTML в кэш происходит, лишь когда поздно придёт сетевой
  ответ; если процесс закрыть раньше — в кэше «залипает» старое.
- **Слой 3 — HTTP-кэш браузера.** На HTML прода **нет** `Cache-Control/ETag/Last-Modified` → сам по себе старое
  не возвращает; ассеты хэшированные (старый хэш не запросится, пока HTML старый). Это следствие, не причина.
- **Слой 4 — серверные кэши данных.** `useCachedAsyncData` (модульный `Map`, TTL) даёт **несвежие данные**, но
  не старый бандл; чистится перезапуском + штампом `buildId`.

### Что сделано
- **`useCachedAsyncData`:** ключ кэша фиксируется ДО `await` (иначе ответ старого запроса кэшировался под
  новым ключом); TTL: товары 1 мин, категории/цена 5 мин. Самодельный buildId-штамп **удалён** (`84837a4`).
- **PWA:** навигации `NetworkOnly`, `html` вне precache → старый HTML не отдаётся. SW возвращён (снят
  `selfDestroying`); стратегия обновлений — `pwa-update-strategy.md`.
- **routeRules:** убран нерабочий `/**/products/**` (хвостовой `/**` требует сегмент); `/sitemap.xml` без
  `static`; blog/news → `swr: 300` (+ подпути); каталог без SWR.
- Guard версии и `PWAUpdateNotice` **удалены** (`84837a4`) — после возврата PWA не нужны.

### Статус и грабли
- Актуальная стратегия кэша/обновлений — `pwa-update-strategy.md`; разбор слоёв выше — исторический.
- **Теги в запросе товаров не применяются** (клик по тегу не меняет выдачу) — отдельная задача.
