# План: раздел «Заготовки» (варенье, консервация, засолка) + обобщение калькулятора

> **Режим:** удалённая работа; реализация — **только в непиковые часы** (7–9 и 13–4 МСК).
> Зафиксировано 28.09.2026. Связанное: `agro-calculator.md` (раздел «Посадка»),
> `refactor-plan.md` (общие компоненты), `1778783966963-style-guide.md` (стиль),

## Цель

Второй «калькуляторный» раздел магазина: **заготовки** (варенье, консервация, засолка и т.п.).
Функционально — та же механика, что «Посадка»: категория каталога + хаб-страница + слайд в панели
каталога (≤ планшета) + калькулятор по режимам + товары + статьи + FAQ + SEO.

## Как добавить новый режим (пример: «Компоты»)

Сейчас нормы — три фиксированных компонента (`jam`, `canning`, `salting`), режимы — реестр в коде.
Чтобы добавить четвёртый режим (например, «Компоты»), нужно:

1. **Strapi (схема):** в `Preserve` добавить поле-компонент `compote` (`preserve.norms`) —
   `backend/src/api/preserve/content-types/preserve/schema.json`, затем деплой API и перезапуск
   (миграция: добавится колонка компонента). `be`-значения норм не нужны — компонент не локализован.
2. **Реестр фронта** (`shared/utils/preserves-modes.ts`): добавить режим
   `{ id: "compote", icon: "mdi:…", key: "modeCompote", dataField: "compote", purpose: "ingredients" }`.
3. **Локали** (`app/locales/garden.ts`): ключ `modeCompote` — ru «Компоты», be «Кампоты».
4. **Расчёт:** после улучшения из п. 7 изменений не требует — нормы берутся по `dataField` из реестра.

**Не требует изменений:** движок `CalcSection`, composable `useGardenCalculator`, строки таблицы
(`rows`), поле ввода, UI (табы и слайды строятся из реестра), SEO. Компонент норм тот же: у «Компотов»
будут пустыми `saltPerKg`/`vinegarPerKg`, а `rows` покажет только заполненные поля.

**Оценка:** ~15–20 минут (после улучшения п. 7).

**Триггер перехода на «Вариант B» (режимы из CMS):** если режимов станет больше 5–6 или их захочет
добавлять контент-менеджер. Тогда нормы — повторяемый компонент `preserve.recipe` с полем `mode`,
а список режимов — данные CMS; добавление режима не требует правок схемы и кода.

## Решение (утверждено 28.09): подход «отдельные данные + общий движок»

Дублировать не нужно. Разделяем два слоя:

| Слой | Решение |
|---|---|
| **Данные (Strapi)** | **Отдельные типы**: `preserve-page` (single type, i18n) и `preserve` (collection, i18n). Гибкость: свои режимы, нормы, SEO, FAQ, независимые переводы ru/be |
| **Кирпичи (компоненты Strapi)** | Общие: `calc.defaults`, `calc.faq-item`, `calc.how-to-step`, `calc.mode` (режим раздела), `seo.seo`. Предметные нормы — в своих типах/компонентах |
| **Код (Nuxt)** | **Один** компонент калькулятора-секции (сейчас `HamburgerGarden.vue`) с пропами данных + один интерфейс расчёта; никаких копий под раздел |
| **Панель** | 4-й слайд: `Категории / Посадка / Заготовки / Меню` (места достаточно — согласовано) |

Отклонено: копия стека под заготовки (двойная поддержка кода и багфиксов), а также общий
`calculator-page` с признаком раздела (single type = один документ, гибкость теряется).

## Целевая модель данных

**`preserve-page`** (single type, i18n, draftAndPublish) — тексты и настройки страницы/слайда:
- `heroTitle`, `heroSubtitle`, `intro` (i18n);
- `defaults` (`calc.defaults`), `faq` (`calc.faq-item[]`), `howTo` (`calc.how-to-step[]`),
  `showCalculator`, `seo` (`seo.seo`);
- `modes` (`calc.mode[]`) — список режимов раздела (см. этап 1).

**`preserve`** (collection, i18n) — «продукт заготовки» (ягода/фрукт/овощ/гриб):
- `name`, `slug`, `image`, `description`, `category`, `products`, `blogs`, `isActive`;
- нормы (свой компонент, напр. `preserve.norms`): сахар/соль/уксус/специи **на кг**, выход
  (банки/литры), сроки/особенности — набор уточняется на этапе наполнения.

Аналогия с «Посадкой»: там `crop` + `calc.planting / seedling / fertilizing`; здесь `preserve` +
свой компонент норм. Общими остаются тексты, FAQ, howTo, seo и **список режимов**.

## Этап 0 — обобщение (сделать ДО «Заготовок»)

Без этого второй раздел потребует копии кода. Разово:

1. **Режимы — данными, а не кодом.** Сейчас в `HamburgerGarden.vue` зашиты `seeds / seedlings /
   fertilizer` (`modeTabs`, `resultFor`, `packagingsByPurpose`, `hasModeDataFor`, `modeInfoFor`),
   и `shared/utils/calc.ts` знает про эти три режима. Вынести: режим = `{ id, label, icon, unit }`
   из CMS (`calc.mode`), состав строк результата определяется режимом.
2. **Расчёт — по общему интерфейсу.** Разделить `shared/utils/calc.ts` на модули с общим типом
   (напр. `calc/types.ts`, `calc/planting.ts`, позже `calc/preserves.ts`): формулы остаются кодом,
   входные нормы и режимы — данными.
3. **Один компонент секции.** `HamburgerGarden.vue` → переиспользуемый компонент (рабочее имя
   `CalcSection.vue`) с пропами `page` (данные `*-page`), `items` (культуры/продукты) и функцией
   расчёта. Раздел не должен ветвиться по коду.
4. **Проверка:** «Посадка» работает как раньше (панель + страница `posadka-i-urozhay`) — регрессия.

## Этап 1 — данные «Заготовок»

1. Компонент `calc.mode` (id, label, icon, unit) — общий для обоих разделов.
2. Компонент норм для `preserve` (сахар/соль/уксус/специи на кг, выход).
3. Типы `preserve-page` (single, i18n) и `preserve` (collection, i18n) — на общих кирпичах.
4. Режимы раздела (напр. «Варенье / Консервация / Засолка») — данные, заполняются в CMS.

## Этап 2 — фронт

1. Слайд «Заготовки» в панели (4-й) — на общем компоненте секции.
2. Страница раздела `/{locale}/zagotovki` по образцу `posadka-i-urozhay`:
   десктоп — калькулятор; телефон — вступление + кнопка «Рассчитать» (открывает панель), статьи, FAQ.
3. Товары раздела — фильтр по связи `preserve.products` (ингредиенты/тара/крышки).
4. Локализация ru/be всех UI-текстов (`locales/*`), aria — `locales/button.ts` / `visuallyHidden.ts`.
5. SEO: мета, разметка (вопросы-ответы, инструкция), хлебные крошки, карта сайта.
