# PWA: стратегия обновления (авто / по кнопке / черновик формы)

Статус: **решено — оставляем `autoUpdate`, вариант «по кнопке» отклонён; доработка черновика формы — в бэклог.**
Дата решения: 19.10.2026.

## Текущее состояние

- `frontend/nuxt.config.ts` → `pwa.registerType: "autoUpdate"`.
- Кэш-стратегия безопасна по свежести: навигации `NetworkOnly`, `html` не в precache,
  у ассетов хэши в именах (см. коммиты `84837a4`, `48e743f`).
- UI обновления нет: `PWAUpdateNotice.vue` удалён в `84837a4`.
- Проверка обновлений: при загрузке/навигации + `periodicSyncForUpdates: 3600` (только **проверка**,
  сама по себе страницу не перезагружает).

## Поведение `autoUpdate` и риск

Новый SW активируется сразу (`skipWaiting` + `clientsClaim`), открытые вкладки/окна приложения
перезагружаются автоматически (предупреждение доков vite-pwa: можно потерять данные формы).

| Данные | Переживают авто-перезагрузку |
|---|---|
| Корзина | да — `useCartStore` → `localStorage('cart')` |
| Тема/фон/размер фона | да — `localStorage` |
| Поля формы заказа (имя, телефон, адрес, комментарий) | **нет** |
| Позиция/фильтры/поиск в открытой сессии | нет (мелочь) |

Перезагрузка случается **только когда вышел новый деплой** (новый SW). Значит риск пропорционален
частоте деплоев и длине открытой сессии, а не трафику как таковому.

## Решение

1. **Оставляем `autoUpdate`.** Сейчас деплои частые, но позже планируется максимум 1 раз в день,
   а то и в 3 дня — тогда окно риска становится пренебрежимым.
2. **Вариант `prompt` + баннер — отложен/отклонён**: добавляет UI, локали (ru/be) и действие
   пользователя ради риска, который при редких деплоях стремится к нулю.
   Вернуться к нему стоит только если: деплои снова станут частыми (несколько в день) **или**
   появятся жалобы на пропажу заполненной формы.
3. **Вариант 3 (в бэклог, не срочно):** сохранять черновик формы заказа в `sessionStorage`.

## Бэклог: черновик формы заказа

Зачем: авто-перезагрузка SW перестаёт быть опасной **и** закрывается независимый сценарий —
случайный reload, уход назад, восстановление вкладки браузером.

Как делать (эскиз):

- Формы: `app/components/OrderForm.vue` и `app/components/show-modal/ShowModalCheckoutForm.vue`
  (проверить, какая актуальна на момент внедрения).
- `sessionStorage` (умирает с вкладкой — не «вечный» след на общем устройстве), ключ вида
  `checkout-draft`.
- Восстановление — при монтировании, если черновик не старше N часов/одного дня.
- Очистка — после успешного создания заказа (и при явном сбросе формы).
- Приватность: имя/телефон/адрес лежат в `sessionStorage` до закрытия вкладки — приемлемо,
  но не писать туда лишнего.
- Локали не нужны (это не UI-текст), кроме eventual подсказки «черновик восстановлен» — если решим её показывать.

## Триггеры пересмотра

- Деплои снова стали ежедневными и частыми (несколько в день) → рассмотреть `prompt`.
- Жалоба «пропали данные формы» → внедрить черновик формы вне очереди.
- Появление реального офлайн-сценария (сейчас его нет: навигации NetworkOnly) → пересмотреть
  стратегию кэша целиком, а не только `registerType`.
