## 29.10 — итог: mask vs path (responsive-карточки)

### Факты (из документации)
- **`clip-path: path()` НЕ масштабируется** — только абсолютные единицы. Для карточки, меняющей ширину
  (1↔2 колонки), форма «плывёт». Источник: README `AstroDriss/inverted-corners-generator`.
- **`mask`** работает при совпадении aspect-ratio (для карточек — фиксированная пропорция). Это responsive-вариант.
- Новые CSS-возможности: `corner-shape: scoop` (Chrome 135+/Safari 18.4+/Firefox 148+),
  `clip-path: shape()` (responsive, но пока не во всех браузерах).

### Решение
- Карточки товаров — **на CSS-маске** (`@include invertedRadius`), она проверена и responsive.
- `UShapeNotch` + path — удалены (не используются): задел на `corner-shape`/`shape()` — в git-истории.
- Кнопка позиционируется **формулой от параметров маски** (`--r`/`--s`), а не «на глаз».

### Инструменты, которые остаются
- `scripts/shot.mjs` — скриншоты без MCP; `potrace` — трассировка; `sharp` — pixel-diff.
- Правила проверки: patterns §7–§9 (кадр целиком, кнопка, состояния).

## 02.11 — вырез не появлялся при первой загрузке (исправлено)

Причина: `compactCards` требовал `filterEverOpened` (флаг ставился только после открытия
фильтра) → при загрузке `compact=false` и маска не включалась; вырез появлялся лишь
после открытия/закрытия панели.

Исправление (`frontend/app/pages/[lang]/products/index.vue`):
`compactCards = mounted && !filterDialogOpen` — `filterEverOpened` удалён.

Проверено: 390 — 2 колонки, вырез на всех карточках сразу при загрузке (без действий с фильтром);
1440 — панель открывается сама → карточки обычные (переворот, без выреза). Гидрейшн чистый.
Вариант «компакт на SSR» (`!filterDialogOpen` без `mounted`) даёт hydration mismatch
(в компакте ClientOnly-модалка) — так делать нельзя.

## 09.11 — равномерный «воздух» (исправлено)

Факт по скриншоту прода (сборка до `a8631c2`): BR плашки = 6px (`--card-radius`), а видимая
кромка карточки = 14.8px (`--notch-r` от маски) → угол «угловатый». В `a8631c2` все углы плашки
= `--notch-r`, это исправлено; на проде ещё старая сборка.

«Воздух» — итог (замеры на 3x, `sharp`, CSS-px):
- было (сборка `a8631c2`): 390 — top 4.4 / left 5.5 / right 4 / bottom 0; 360 — top 4.9 / left 6.0 / right 3.7.
- стало: 390 (44px) — **top 5.3 / left 5.0 / right 4.7 / bottom 0, дуга 5.5**;
  360 (42px) — **top 5.0 / left 5.3 / right 4.7 / bottom 0, дуга 5.2**.

Формулы (вместо коэффициентов «на глаз»), в `&_compact`:
- `--notch-s: (--notch-size + --notch-gap) / 2` — верх;
- `--notch-r: --notch-size / 4 + 0.75 * --notch-gap` — лево/дуга;
- TL плашки = `--notch-r + --notch-gap` (концентричен дуге; TR/BL/BR = `--notch-r`).
- CQ ≤170px: 42px + gap 5 + поправка `r = 0.329S`, `s = 0.571S` (у маски абсолютные px,
  иначе верх на ~1px меньше боков).

Поправка по устройству (09.11, вечер): на реальном телефоне верх выходил на ~1.2px больше,
чем в headless-замерах (6.5 против 5.0 по бокам). Сдвинули верхнюю кромку к плашке:
`s -= 0.75px`, `r += 0.35px` (компенсация левого). Локально 390: top 4.3 / left 5.0.

Устройство пользователя попадает в CQ-вариант (42px, контейнер ≤170) — правку 44px оно не
видело. Та же поправка применена и к CQ: `r = 0.3373S`, `s = 0.5531S` (было 0.329/0.571).
На устройстве: top 6.2 / left 4.7 / right 5.1 → ожидаемо ≈4.5 / 4.7 / 5.1.

Грабли замеров (важно):
- 1x-скриншот даёт ±1px шум: TL-радиус «не влиял» — на 3x видно +1.3px у дуги. Мерить только 3x.
- Плашку искать по DOM-прямоугольнику, а не по «зелёным» пикселям (иконки/текст карточки).
- «Воздух» мерить только на прямых участках кромок: от `l + TL` до `r - TR`, иначе в медиану
  попадает скругление и значение занижается.
- Выборка «вне рамки» от самой рамки даёт air=0 — рамка тоже не-светлая.
