## Осталось (только это)
1. **SVG `clip-path: path(...)` на тестовой карточке** (`ir-demo`): рядом с CSS-маской, при одинаковых параметрах; path генерировать из параметров (ширина, высота, радиус, вырез, скругление). Сравнить форму/зазоры/цену. По результату — решение о переносе выреза на path.

- Вырез (CSS-маска) — **только в компактном режиме** (фильтр закрыт); на главной и при открытом фильтре переворота нет — выреза тоже.
- Кнопка: в обычном режиме — в потоке, нижний ряд `__bottom-items` (вариант `add`); в компакте — `_add_plate` (`absolute`, низ по кромке карточки).

- Горизонтальный скролл: `100vw` → `100dvw` (`--container-edge`, ChatAssistant). Проверено: `overflow: false`.
- Демо-мусор удалён: `u-button_notch_v1…5`, `.product-card_geo*`, `:add-variant`, `translateZ`.

## Грабли (не повторять)
- `translateZ(0)`/промоут слоя **ломает маску** — вырез пропадает.
- `.product-card_geo1…5` перекрывал `--notch-*` и «съедал» новые значения.
- Замена варианта `add` без перечисления состояний → теряется `btn_add_is-added` (галочка).

## 29.10 — итог: mask vs path (responsive-карточки)

### Факты (из документации)
- **`clip-path: path()` НЕ масштабируется** — только абсолютные единицы. Для карточки, меняющей ширину
  (1↔2 колонки), форма «плывёт». Источник: README `AstroDriss/inverted-corners-generator`.
- **`mask`** работает при совпадении aspect-ratio (для карточек — фиксированная пропорция). Это responsive-вариант.
- Новые CSS-возможности: `corner-shape: scoop` (Chrome 135+/Safari 18.4+/Firefox 148+),
  `clip-path: shape()` (responsive, но пока не во всех браузерах).

### Решение
- Карточки товаров — **на CSS-маске** (`@include invertedRadius`), она проверена и responsive.
- `UShapeNotch` + path — удалены (не используются): задел на `corner-shape`/`shape()` — в git-истории.
- Кнопка позиционируется **формулой от параметров маски** (`--r`/`--s`), а не «на глаз».

### Инструменты, которые остаются
- `scripts/shot.mjs` — скриншоты без MCP; `potrace` — трассировка; `sharp` — pixel-diff.
- Правила проверки: patterns §7–§9 (кадр целиком, кнопка, состояния).

## 02.11 — вырез не появлялся при первой загрузке (исправлено)

Причина: `compactCards` требовал `filterEverOpened` (флаг ставился только после открытия
фильтра) → при загрузке `compact=false` и маска не включалась; вырез появлялся лишь
после открытия/закрытия панели.

Исправление (`frontend/app/pages/[lang]/products/index.vue`):
`compactCards = mounted && !filterDialogOpen` — `filterEverOpened` удалён.

Проверено: 390 — 2 колонки, вырез на всех карточках сразу при загрузке (без действий с фильтром);
1440 — панель открывается сама → карточки обычные (переворот, без выреза). Гидрейшн чистый.
Вариант «компакт на SSR» (`!filterDialogOpen` без `mounted`) даёт hydration mismatch
(в компакте ClientOnly-модалка) — так делать нельзя.

## 09.11 — равномерный «воздух» (исправлено)

Факт по скриншоту прода (сборка до `a8631c2`): BR плашки = 6px (`--card-radius`), а видимая
кромка карточки = 14.8px (`--notch-r` от маски) → угол «угловатый». В `a8631c2` все углы плашки
= `--notch-r`, это исправлено; на проде ещё старая сборка.

«Воздух» — итог (замеры на 3x, `sharp`, CSS-px):
- было (сборка `a8631c2`): 390 — top 4.4 / left 5.5 / right 4 / bottom 0; 360 — top 4.9 / left 6.0 / right 3.7.
- стало: 390 (44px) — **top 5.3 / left 5.0 / right 4.7 / bottom 0, дуга 5.5**;
  360 (42px) — **top 5.0 / left 5.3 / right 4.7 / bottom 0, дуга 5.2**.

Формулы (вместо коэффициентов «на глаз»), в `&_compact`:
- `--notch-s: (--notch-size + --notch-gap) / 2` — верх;
- `--notch-r: --notch-size / 4 + 0.75 * --notch-gap` — лево/дуга;
- TL плашки = `--notch-r + --notch-gap` (концентричен дуге; TR/BL/BR = `--notch-r`).
- CQ ≤170px: 42px + gap 5 + поправка `r = 0.329S`, `s = 0.571S` (у маски абсолютные px,
  иначе верх на ~1px меньше боков).

Поправка по устройству (09.11, вечер): на реальном телефоне верх выходил на ~1.2px больше,
чем в headless-замерах (6.5 против 5.0 по бокам). Сдвинули верхнюю кромку к плашке:
`s -= 0.75px`, `r += 0.35px` (компенсация левого). Локально 390: top 4.3 / left 5.0.

Устройство пользователя попадает в CQ-вариант (42px, контейнер ≤170) — правку 44px оно не
видело. Та же поправка применена и к CQ: `r = 0.3373S`, `s = 0.5531S` (было 0.329/0.571).
На устройстве: top 6.2 / left 4.7 / right 5.1 → ожидаемо ≈4.5 / 4.7 / 5.1.

## 09.11 — 3D-переворот плашки (сделано)

По клику (добавление/удаление) плашка переворачивается вокруг оси Y, как карточка:
две грани в слоте `UButton` (`__plate-face` front/back), `transform-style: preserve-3d`,
`backface-visibility: hidden`, `perspective` на самой кнопке; класc `_is-added` → `rotateY(180deg)`,
transition 0.5s. `Vue <Transition>` не нужен — это не enter/leave, а состояние.

Фон и рамку теперь рисуют грани; сама кнопка прозрачная (иначе при повороте видна плоская
подложка). `.button-content` тянем через `:deep()` — он создаётся внутри UButton и scoped-атрибут
родителя на него не попадает (без этого грани были 2×2). `prefers-reduced-motion` — без анимации.
Замеры зазоров после правки не изменились (390: 4.3/5.0/4.7, 360: 3.0/5.3/4.7).

## 11.11 — вырез без переворота слоя (замыленность края)

На Android край маски мылился (~4 CSS px) при резком рендере локально. Причина: маска лежала
на трансформированном слое (`__surface` с `scaleY(-1)`) — композитный слой растеризуется
в текстуру пониженного разрешения.

Решение: новый миксин `invertedRadiusBottomRight` — вертикальное зеркало пяти слоёв, вырез
строится сразу в правом нижнем углу, `transform` с маскированного слоя снят (и контр-переворот
с контента). При зеркале прозрачный квадрант коники переезжает из 0–25% в 25–50%; набор
выходит на ~1.3px мельче — компенсация в карточке `r +0.17px`, `s +0.67px` (замеры совпали
с прежними: 4.33 / 5.00 / 4.67, дуга 4.50).

Грабли замеров (важно):
- 1x-скриншот даёт ±1px шум: TL-радиус «не влиял» — на 3x видно +1.3px у дуги. Мерить только 3x.
- Плашку искать по DOM-прямоугольнику, а не по «зелёным» пикселям (иконки/текст карточки).
- «Воздух» мерить только на прямых участках кромок: от `l + TL` до `r - TR`, иначе в медиану
  попадает скругление и значение занижается.
- Выборка «вне рамки» от самой рамки даёт air=0 — рамка тоже не-светлая.

## 11.11 — маска вырезом через SVG-путь

Дуга выреза «мылилась» на телефоне, хотя локально была резкой: прямые кромки строятся
коническими слоями (жёсткие стопы), а дуга — радиальным градиентом, и его сглаженный край
на GPU растягивался в 3–4 CSS px. Снятие `scaleY(-1)` с маскированного слоя не помогло.

Решение: миксин `notchMask($w, $h, $r, $s)` — маска из SVG-пути в data-URI
(`mask-image` + `mask-size: 100% 100%`), путь растеризуется с нормальным AA на любом DPR.
Геометрия та же (замеры 390: top 6.33 / left 6.00 / right 5.67 / low 0, дуга 6.3).
Градиентный `invertedRadiusBottomRight` удалён как неиспользуемый.

Воздух: плашка уменьшена относительно выреза (`--plate-size` 42, `--plate-inset` 6) —
+2px сверху и по бокам, снизу 0. Временные варианты зазора — классы `product-card_air-a/b/c`
на первых трёх карточках (42/6, 40/7, 38/8).

Правка SVG-маски (11.11, вечер): первая версия пути рисовала вырез как «закруглённый
прямоугольник» — не было скруглений r на внешних углах выреза (верх-право и низ-лево),
и дуга шла не туда (sweep). Итог: два подпути + `fill-rule="evenodd"` (карточка минус
вырез), вырез — с дугой `s` на внутреннем углу и скруглениями `r` на внешних.
Замеры 390: 6.33 / 6.00 / 5.67 / 0, дуга 6.37 — совпадает с прежней геометрией.

## 11.11 — единый источник геометрии + вариант 2 для угла

- В `ProductCard.vue` геометрия выреза задана SCSS-константами `$plate-size / $notch-gap`,
  из них считаются `$notch-r = size/4 + 0.75·gap`, `$notch-s = (size+gap)/2` и **та же**
  пара уходит в маску (`notchMask`) и в CSS-переменные плашки. Меняешь размер плашки —
  маска пересчитывается вместе (проверено: 50.5/6 → вырез 62.5×56.5, воздух ровно 6).
- Плашка увеличена на 8px: 42.5 → **50.5**, зазор 6.
- Угол выреза снизу слева: вместо касательной дуги — **кубическая кривая** (касание к нижней
  кромке попадало на границу пикселя и на телефоне давало смазанный уступ). Верхний правый
  угол не тронут.
- Временные варианты (`wide-a/b/c`) удалены, всё на одном варианте.

Правка 12.11: TL-радиус плашки = `s − gap` (было `r + gap` с поправкой −1.5).
Только при этом условии центр угла плашки совпадает с центром дуги выреза и зазор
одинаков по всей дуге. Проверено расчётом: центры совпадают (distance 0.000),
зазор в угле = 10.00 при кромочных 10; для CQ-варианта (46px) — то же.

Правка 12.11 (вечер): базовый вариант — плашка В УГЛУ (заподлицо справа и снизу).
Геометрия: `s = (plate+gap)/2`, вырез `X = Y = plate+gap`, `r = (X − s)/2`,
`TL плашки = s − gap` (концентричен дуге), `TR/BL = 12` (меньше, они у прямых кромок),
`BR = r` (совпадает с кромкой карточки). Зазор 8px (было 10).

12.11 (вечер): убрана серая полоса под ценой (`__bottom-items` → transparent);
в маску добавлен прямоугольный вырез в левом верхнем углу под статус
(104×30, внутренний радиус 6). `ProductStatus` в компакте вынесен НАД маской
(`.product-card__status`, z-index 160, светлый текст), размеры в % от карточки —
совпадают с вырезом при любом размере. В обычном режиме статус остаётся в `__top-items`.
