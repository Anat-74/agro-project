# Refactoring Plan — Agro Market

## Правила работы
- После каждого шага — краткий отчёт о сделанном.
- Переход к следующему шагу ТОЛЬКО после твоего одобрения.
- Шаги выполняются строго последовательно, один за другим.
- Ты проверяешь что всё работает, ничего не сломалось, и только потом говоришь «дальше».

## Контекст проекта

### Tech Stack
- Nuxt 4.4.8, Nitro 2.13.2, Vite 7.3.5, Vue 3.5.38
- SCSS (BEM), TypeScript, Pinia, Strapi 5.48.1, Netlify SSR

### Strapi v5 — критичные правила

1. **locale** — всегда внутри `filters` с `$eq`
2. **deep filters** — только вложенный синтаксис (dot notation `"category.slug"` → 400 ошибка с `@nuxtjs/strapi`)
3. **populate** для компонентов — без поля `id`
4. **sort** — обязательно массивом: `sort: [value]`
5. **`as any`** — обязательно для всех `find()` с generic-типами
6. **`getProductLink()`** — требует populated `category`/`subcategory`
7. **`fields`** — избегать `id` для media и components

### Single Media для изображений категорий/подкатегорий
- Поле `image`: теперь single media (не массив). Тип: `Image[]` → `Image | null`
- Доступ: `item.image?.url` (не `item.image[0]?.url`)
- Продукты: `image` остаётся массивом, `mainImage` — single media

### Соглашение об именовании dialog-компонентов
- **Панель** (без backdrop, `useShowMethod: true`): префикс `Show`. Пример: `ShowHamburger.vue`
- **Модальное окно** (с backdrop, `useShowMethod: false`): префикс `ShowModal`. Пример: `ShowModalDiscountProduct.vue`
- **Чистая модалка** без кнопки открытия: суффикс `Modal`. Пример: `ConfirmDeleteModal.vue`

## Web Vitals (мониторинг производительности)

### Структура
- `composables/useWebVitals.ts` — сбор LCP, CLS, INP
- `server/api/web-vitals.post.ts` — приём метрик
- `server/api/web-vitals.get.ts` — просмотр (GET /api/web-vitals)
- `server/data/web-vitals.json` — файл с данными

### Как проверить в новой сессии
1. Запустить `npm run dev` (frontend)
2. Походить по страницам сайта
3. Открыть `http://localhost:3000/api/web-vitals` — JSON со всеми метриками
4. Или прочитать файл: `cat frontend/server/data/web-vitals.json`

### Известные проблемы
- **CLS** — сбрасывается при смене pathname (накопление между страницами пофикшено)
- **LCP** — холодный старт после сборки может выдавать 37-38s (единоразово)

# Личный кабинет (User Profile) — план реализации

Strapi Users & Permissions + JWT.

### API эндпоинты (встроенные в Strapi)
| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/api/auth/local/register` | Регистрация |
| POST | `/api/auth/local` | Вход |
| GET | `/api/users/me` | Текущий пользователь |
| POST | `/api/auth/forgot-password` | Сброс пароля |
| POST | `/api/auth/reset-password` | Новый пароль |

### Бэкенд (Strapi)
- **A1.** Права доступа: Public → auth, Authenticated → order по email
- **A2.** Связь Order → User (по email или relation)
- **A3.** Email-провайдер

### Фронтенд (Nuxt)
- **B1.** `stores/useAuthStore.ts` — user, token, login/register/logout
- **B2.** `composables/useAuth.ts` — обёртка с isAuthenticated
- **B3.** `middleware/auth.ts` — редирект если нет токена
- **B4.** Страницы: login / register / cabinet / cabinet/[orderId]
- **B5.** Компоненты: AuthLogin, AuthRegister, OrderHistory
- **B6.** Локали: `locales/auth.ts` + `locales/cabinet.ts`

**Оценка времени:** ~2.5 часа
